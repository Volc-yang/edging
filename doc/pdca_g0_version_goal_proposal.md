## 2. 下一版本的可测开发目标

暂用过程标识 `V-next`，正式产品版本号和范围由统筹冻结。建议目标为：在确定的一台目标机器和版本化场景上，完成一条可复现、可独立验收的端到端纵切，逐项给出目标覆盖、权威边界、集成、视觉、性能、可靠性和成本结论。现有 Chaos/Realism 是候选基线证据，不能替代新版本检查。

| 目标 | 暂定可测完成标准 | 后续 owner / 证据 |
| --- | --- | --- |
| O1 范围可追踪 | 100% 本版本必需需求映射到契约版本、叶任务、检查门；至少 1 条端到端场景写明起点、动作、可观测终点与超时 | 统筹/G1；需求—任务—证据矩阵与场景脚本 |
| O2 可重建与集成 | 固定输入从干净任务环境完成构建和启动；同一场景至少 2 次独立进程运行有完整记录 | G3；准确集成提交、依赖清单、构建/启动原始日志 |
| O3 权威与恢复 | 契约要求的全部观察动作逐项前后比对权威摘要，非授权写入为 0；固定输入重演和 1 次中断恢复满足已冻结对照规则 | G2a/G3/G4；动作、摘要、重演和恢复记录；跨平台等价性另定 |
| O4 可见与可操作 | 场景脚本全部必需检查点有真实 Metal 图像及操作结果，独立 reviewer 能按预设视觉标准逐项判断 | G2c/G4；参考图、实际帧、输入记录与评审表 |
| O5 性能有实测 | 固定分辨率/负载/路线采集 CPU/GPU 帧时间和内存，按冻结数值逐项判定；FPS 配置回读不算实测 | GQ/G4；未过滤 trace、采样配置、统计方法和摘要 |
| O6 AI/物理边界可检验 | 本版本若纳入 AI 或 Genesis，100% 已冻结接口必需用例有结果，包含正常与拒绝/错误路径；未纳入须有明确范围裁决 | G1/G2b/G2d/G4；固定评估输入、版本/配置及请求结果 |
| O7 交付可审计 | 100% 必需门可追到准确提交、输入、方法、阈值版本、原始证据、检查者及实际结论；父级集成与独立验收均执行 | GQ/G4/G5；证据索引、PR、裁决和下轮 ready 队列 |

以上计数均为建议阈值，须与第 4 节一起批准；未冻结前只报告观测值。载具登陆若被选入本版本，须先由产品负责人给出其场景与成功信号，G1 再定义接口和验收；本提案不推导驾驶、登陆、胜负、物理参数或演化规则。

非目标：完整数字宇宙、生产规模、多平台发布、完整载具/玩法系统均不默认进入本次纵切；程序代理不等于最终写实美术；不新增世界法则、不批准实验算法为产品规则、不改 UE 源码、不合并主工作区脏改动。范围排除必须在冻结时明确，不能到验收失败后追认。

## 5. 依赖与 ready 条件

G0 提案提交与 G0 冻结接受是两个事件。G0 的 `accepted` 要求 F0/F1/F2 的适用状态经统筹确认，版本目标/非目标、必需门、环境、规模、预算与阈值全部明确，且独立文档审查和跨文档集成检查通过；数值仍开放的必需门阻止接受。

| 节点 | depends_on / ready_condition | 当前建议 |
| --- | --- | --- |
| G0 审查 | 固定输入和独占写范围；本文交付后由非 owner 检查 | 可准备审查，等待实际 PR 与 C2 |
| G1 架构与接口 | G0 accepted；范围和质量门版本固定；owner/独占路径/资源/预算明确 | 尚未 ready；可做被明确授权的只读调查 |
| GQ 证据基础 | G0 accepted；环境、证据字段与预算固定；写路径不与 G1 重叠 | 与 G1 同时 ready 后可并行 |
| G2a–d | G1 accepted 且本分支共享接口已冻结；只派本版本必需叶节点 | 等待；不得猜测未定产品语义开始实现 |
| G3 | 本版本必需 G2 叶节点和 GQ accepted，接口兼容与集成资源可用 | 等待；不要求未纳入版本的可选分支完成 |
| G4 | G3 accepted，准确集成提交/场景/阈值与独立验证者就绪 | 等待；实现 owner 不能自证独立验收 |
| G5 | G4 已给出实际逐门结果与裁决 | 可复盘失败或缺证；发布接受仍要求必需门全过或有明确豁免 |

依赖顺序为 G0 → {G1,GQ} → 必需 G2 → G3 → G4 → G5，其中 G3 另依赖 GQ；不新增反向边。G1/GQ 调研发现目标不可测时提出 G0 新版本，冻结受影响下游，不把修改塞入旧检查结果。

## 7. 评价与下一轮入口

评价逐维度记录目标覆盖、契约、集成、真实运行、过程可控和风险/成本，不设能掩盖失败的加权总分。`pass` 需要预先冻结阈值、有效身份/信号及实际满足；`fail` 需要有效观察违反标准；缺信号、未执行或阈值未冻结为 `inconclusive`。尚待执行的检查排程为 `planned`；一旦对缺证作裁决，用 `inconclusive`，不能当作通过。

出现失败先保存原始证据，分清事实、原因假设和未知，将返工归到最小节点及受影响下游；不重写旧 run。门变更生成新版本，记录旧/新值、原因、裁决与受影响节点。豁免必须由统筹记录明确依据和剩余影响；owner 不自行降低门槛。独立审查、PR 合并和父级验收分别登记。
