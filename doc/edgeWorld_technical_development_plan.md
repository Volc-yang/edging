### **软件开发计划：易之世界 (edgeWorld)**

---

#### **第一阶段：核心引擎与可视化原型 (客户端)**

**目标**: 搭建一个可交互的游戏世界雏形，验证核心的程序化生成与渲染能力。

1.  **项目基础架构 (1-2周)**
    *   **任务**: 巩固并优化当前的Xcode项目结构，确保 `edge-world Shared` 内的代码能高效地被 macOS, iOS, tvOS 等多个目标平台复用。
    *   **技术点**: Swift Package Manager, Xcode Target 配置, 文件共享策略。

2.  **程序化世界生成 (3-4周)**
    *   **目标**: 搭建一个可交互的游戏世界雏形，验证核心的程序化生成与渲染能力。
    *   **任务细分**:
        1.  **设计：定义八卦与地形的映射规则**
            *   **目标**: 建立一套清晰的规则，将八卦的哲学含义转化为具体的地形特征。
            *   **子任务**:
                *   为每个卦象（乾、坤、震、巽、坎、离、艮、兑）设定基础地形属性，例如：
                    *   **艮 (山)**: 高海拔、崎岖度高。
                    *   **坎 (水)**: 低海拔、形成山谷或湖泊。
                    *   **坤 (地)**: 平原、地形平缓。
                    *   **震 (雷)**: 可能代表地貌的断裂、悬崖。
                    *   ...以此类推。
                *   确定如何将这些卦象组合应用到整个世界地图上（例如，将世界划分为几个大区域，每个区域赋予一个主卦象）。

        2.  **实现：高度图 (Heightmap) 生成算法**
            *   **目标**: 编写代码，根据步骤1的规则生成一个二维数组，其中每个值代表地形的高度。
            *   **子任务**:
                *   创建一个新的Swift文件，例如 `TerrainGenerator.swift`。
                *   在该文件中，创建一个 `TerrainGenerator` 类。
                *   实现一个函数 `generateHeightmap(width: Int, depth: Int) -> [Float]`。
                *   在此函数内部，使用柏林噪声 (Perlin Noise) 算法生成基础地形。
                *   根据预设的卦象区域，调整噪声的参数（如频率、振幅）来体现不同卦象的地貌特征（例如，“艮”区域增加振幅，“坤”区域减少振幅）。

        3.  **实现：地形网格 (Mesh) 构建**
            *   **目标**: 将生成的高度图数据转化为可供 Metal 渲染的顶点和索引数据。
            *   **子任务**:
                *   在 `TerrainGenerator` 类中，添加一个函数 `createMesh(from heightmap: [Float]) -> (vertices: [Vertex], indices: [UInt32])`。
                *   遍历高度图，为每个点创建一个 `Vertex` 结构体（其定义在 `ShaderTypes.h` 中），设置其 `position` (x, y, z)，其中 `y` 来自高度图。
                *   为每个顶点计算法线 (`normal`)，用于后续的光照计算。
                *   生成索引数据，将顶点连接成三角形，构成网格。

        4.  **渲染：在 Metal 中绘制地形**
            *   **目标**: 将构建好的地形网格数据发送到 GPU 并显示在屏幕上。
            *   **子任务**:
                *   修改 `Renderer.swift` 文件。
                *   在 `Renderer` 的初始化方法 `init(metalKitView:)` 中，调用 `TerrainGenerator` 来生成网格数据。
                *   创建新的 `MTLBuffer` 用于存储地形的顶点和索引。
                *   修改 `draw(in:)` 方法，添加一个新的渲染指令 (`MTLRenderCommandEncoder`) 来绘制地形的 `MTLBuffer`。
                *   可能需要调整 `Shaders.metal` 中的顶点着色器和片元着色器，以正确处理地形顶点数据，并根据高度等信息为其上色。

        5.  **集成与验证**
            *   **目标**: 确保所有模块协同工作，最终在应用启动时能看到程序化生成的地形。
            *   **子任务**:
                *   在 `GameViewController.swift` 中，确保 `Renderer` 被正确初始化。
                *   运行 `edge-world macOS` 应用。
                *   验证屏幕上是否成功渲染出一个3D地形。

3.  **动态时间系统与渲染管线 (2-3周)**
    *   **任务**: 基于“四象”的时间理论，建立全局时间系统，并将其与视觉表现关联。
    *   **技术点**:
        *   实现一个驱动游戏世界逻辑心跳的计时器。
        *   将“四象”映射为一天中的不同时段（如少阳-晨，太阳-午）或四季。
        *   在 `Metal` Shaders 中，根据时间改变光照方向、颜色和天空盒，实现基础的昼夜循环。

4.  **实体与交互原型 (2-3周)**
    *   **任务**: 引入基础的实体组件系统 (ECS) 架构，并实现玩家在世界中的基本漫游。
    *   **技术点**:
        *   设计 `Entity`, `Component`, `System` 的核心数据结构。
        *   创建简单的 `PositionComponent` 和 `RenderComponent`。
        *   实现一个第一人称或第三人称相机，响应键盘和鼠标输入，允许玩家自由探索生成的世界。

---

#### **第二阶段：服务器搭建与“降神”玩法验证**

**目标**: 建立客户端与服务器的通信，并验证核心的“降神”异步玩法。

1.  **服务端技术选型与架构设计 (1周)**
    *   **任务**: 确定后端开发语言与框架。考虑到性能和Swift生态的亲和度，`Vapor` (Swift) 或 `Go` 是不错的候选。
    *   **技术点**: 性能评估, 开发效率, 与客户端的数据模型（如 `ShaderTypes.h` 中的结构）的兼容性。

2.  **基础通信与数据同步 (3-4周)**
    *   **任务**: 搭建一个可以处理长连接和HTTP请求的服务器，并实现客户端与服务器的首次握手。
    *   **技术点**:
        *   使用 WebSocket 实现客户端与服务器之间的实时状态同步。
        *   定义基础的网络协议 (Protobuf 或 JSON)，用于交换玩家位置、状态等信息。
        *   客户端连接成功后，在服务器上生成对应的玩家角色实体。

3.  **“降神”玩法原型 (4-5周)**
    *   **任务**: 实现最简化的“降神”循环：玩家在线时控制角色，离线后角色由AI接管。
    *   **技术点**:
        *   **状态机**: 为玩家角色设计“玩家控制”和“AI控制”两个核心状态。
        *   **离线AI代理**: 在服务器上，为离线玩家实现一个简单的AI代理，例如，在一定范围内随机移动（寻路算法占位符）。
        *   **数据持久化**: 使用数据库 (如 PostgreSQL 或 MongoDB) 存储角色的核心数据（位置、基本属性），确保服务器重启或玩家重连后状态不丢失。

#### **第三阶段：“易之法则”核心算法实现**

**目标**: 将游戏最独特的哲学系统转化为服务器端的核心逻辑。

1.  **“道生万物”生命周期模拟 (4-6周)**
    *   **任务**: 在服务器上实现基于“阴阳”二气和生命周期的动态生态系统。
    *   **技术点**:
        *   **能量系统**: 定义世界总能量为1的常量。所有实体（生物、植物）都拥有 `yin_qi` 和 `yang_qi` 属性。
        *   **生命周期状态机**: 为实体实现“初生、鼎盛、衰败、消亡”的四阶段状态机。状态变迁由其内部阴阳比例和与环境的能量交换决定。
        *   **涌现行为**: 模拟大量实体在各自生命周期内的交互，观察宏观生态的自然演变（例如，草的生长与消亡会影响食草动物的数量）。

2.  **“定数”与“变数”系统 (5-7周)**
    *   **任务**: 设计并实现玩家行为的分析模型，以及由此产生的因果反馈机制。
    *   **技术点**:
        *   **64维行为向量**: 设计一个数据结构，用于量化和记录玩家在64个维度上的关键行为（例如，战斗、探索、社交、创造、毁灭等）。
        *   **行为日志系统**: 在服务器端建立一个高效、可扩展的日志服务，用于记录与64维向量相关的玩家行为。
        *   **“定数”生成算法 (原型)**: 在一次轮回结束时，分析玩家的行为日志，通过加权、聚类等算法，将其映射到64卦中的某一卦，从而生成下一世的初始剧本（例如，“谦”卦开局可能是出身名门但需保持谦逊）。
        *   **“熵”值与“变数”触发**: 实时计算玩家行为对世界秩序的扰动（“熵”）。当“熵”值达到某个阈值时，动态地为玩家生成一个独特的“变数”事件或副本。

---

#### **第四阶段：内容填充与功能扩展**

**目标**: 在坚实的技术框架之上，丰富游戏内容和可玩性。

*   **任务**:
    1.  **美术资源整合**: 导入高质量的3D模型、纹理、特效，并与程序化生成系统结合。
    2.  **任务/剧情系统**: 开发一套能够承载“定数”和“变数”所生成内容的任务系统。
    3.  **高级AI**: 为NPC和生物设计更复杂的行为树 (Behavior Trees) 或状态机。
    4.  **核心玩法循环**: 完善战斗、制造、社交等核心玩法系统。
    5.  **UI/UX**: 设计并实现符合游戏哲学理念的用户界面。

---

#### **第五阶段：测试、优化与部署**

**目标**: 打磨产品，确保其稳定性、性能和可扩展性。

*   **任务**:
    1.  **性能分析与优化**: 对客户端渲染帧率和服务器响应时间进行深度剖析和优化。
    2.  **游戏性平衡**: 调整“能量”、“熵”、“定数”等核心系统的数值，确保游戏体验良好。
    3.  **自动化测试**: 编写单元测试和集成测试，特别是针对核心算法的正确性。
    4.  **服务器运维**: 制定服务器的部署、监控、备份和弹性伸缩方案。
