# edging.cloud 4D 引擎主页方案树

状态：方案已审定；由主任务负责 Site 生命周期，实施从静态单页开始。

## 目标

为 `www.edging.cloud` 准备一个清楚、可信、响应式的 edgeWorld 4D 游戏/世界引擎研发主页。它要说明核心想法和当前原型路线，同时明确项目仍处于研究与原型阶段。

## 固定事实与内容约束

- 对外品牌使用 **edgeWorld**；域名目标为 `www.edging.cloud`。
- 4D 指持久世界状态按显式逻辑时间和规则演化，并从状态/历史生成观察结果；不是给普通 3D 渲染增加时间轴。
- UE5 发布版、Runtime 插件和现有 Renderer 是首选集成/呈现路径；Genesis 是被研究的物理适配器。
- 当前仅有有限实验契约和单刚体 worker 纵切；UE↔worker↔Genesis 的端到端验收未完成。
- 不宣称生产就绪、跨平台确定性、多人规模、无限世界、可下载/可玩的完整产品。
- 不虚构联系邮箱、社区、下载或公开仓库链接。页面以英文为主。

## 方案树

```text
H0  edging.cloud 4D 引擎主页
├── P1 信息架构与事实校核 [方案完成，主任务审定]
│   ├── Hero：Worlds that keep evolving through time.
│   ├── Explain：渲染观察状态；逻辑 tick 推进状态
│   ├── Architecture：UE5 plugin → edgeWorld worker → Genesis adapter → UE5 Renderer
│   ├── Experiments：显式推进、存档续算、历史只读观察
│   └── Status：研究原型；集成验收进行中
├── P2 站点与静态源配置 [主任务负责]
│   ├── 检查/复用项目中的 Sites 配置；当前无配置、账户无可复用 Site
│   ├── 注册一次 Site 并持久化准确 project ID
│   └── 以独立、窄范围文件承载静态首页和托管配置
├── P3 首页实现 [依赖 P1、P2]
│   ├── 单页叙事体验，深色空间/时间层次视觉
│   ├── 响应式与基础可访问性
│   └── 不添加未经要求的表单、路由或伪交互
├── P4 预览与静态检查 [依赖 P3]
│   ├── 本地页面正常响应
│   ├── 检查资源引用、标记与脚本语法
│   └── 展示本地预览
└── P5 发布与域名接入 [依赖 P4]
    ├── 发布主页并确认部署成功
    ├── 请求 Sites 为 www.edging.cloud 提供绑定/验证记录
    └── DNS 操作留给域名持有人按返回记录配置
```

## 执行边界

- 两个规划提案（信息架构、Sites 构建/发布路径）均只读完成；主任务合并、消除冲突并审定本方案树。
- Sites 工具、hosting manifest、源仓库推送和发布仅由主任务这一 Site owner 操作；子 Agent 不触碰站点生命周期。
- 页面实现限定在本轮专属站点文件；保留主工作区既有未提交改动，不改动、暂存或提交它们。
- 默认英文单页；如需中文版本，可后续迭代添加。
