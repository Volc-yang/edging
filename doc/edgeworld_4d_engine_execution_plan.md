# edgeWorld 4D 引擎执行计划

版本：0.3（UE5 发布版插件优先路线）
日期：2026-10-10
状态：按用户决策更新路线；阶段门通过后再进入下一阶段

## 1. 目标与工程判断

edgeWorld 的前提是建立自有的 4D 世界引擎。**优先使用 Unreal Engine 5 发布版的成熟引擎与渲染能力**，通过项目插件/模块和适配层连接 edgeWorld 权威状态、逻辑时间、规则演化与 Genesis 物理层。目标是把 4D 变化规则做成可组合、可调用、可追溯的模块，并从持久世界状态生成时间相关的观察结果。仅当发布版 UE5 经实测无法满足已批准的 4D 契约时，才评估改动 UE5 引擎源码；源码 fork 不是默认前提。

这里的 4D 指**持久世界状态在时间规律下持续演化，并可从任意观察时刻与观察位置生成呈现**；它不是给 3D 场景附加一个时间坐标，也不是在现有逐帧渲染上堆叠动画。第一条路线保留 UE5 场景/Actor/Renderer 作为可替换观察投影，不能把 Actor 生命周期或逐帧渲染当权威世界时钟/状态。阶段 1/2 先验证 UE5 发布版插件、进程适配与现有 Renderer；只有证据显示已批准契约无法实现，才比较旁路或源码改造，并审查许可与分发影响。

引擎由四个同等重要的核心构成：

1. **世界状态存储**：世界如何被定义、分区、版本化、保存、恢复与归档。
2. **时间与规则调度**：时间如何推进，哪些规则何时被调用，依赖、优先级与冲突如何仲裁。
3. **演化执行**：变化如何产生、传播、累积、衰减，及其因果如何追踪和回放。
4. **4D 呈现**：如何从世界状态及其时间历史生成观察结果；呈现系统不得反向决定世界状态。

“不易、变易、简易”分别约束不变量和规则边界、状态变化与传播、以及规则模块的可组合性和可解释性。成熟引擎的验收不以功能数量衡量，而以这些核心契约可执行、可扩展、可回放、可观测为准。

## 2. 定位现有成果

现有 Python 运行时、快照/历史、规则原型、Godot 消费端和 64 卦结构，是**4D 引擎的研究与原型资产**。它们证明部分世界规则及跨端数据消费可行，但尚不等于成熟的 4D 引擎，也不应成为最终运行时边界。UE5 源码改造涉及的渲染器、对象模型、资产/存档管线、调度器和工具链目前尚未完成专项盘点。

已可复用：

- `engine/chapter_one_runtime.py`、`engine/subjective_world.py`：确定性规则仲裁与一轮主体状态变化。
- `engine/snapshot_store.py`、`engine/chapter_one_history.py`：原子快照、轮次归档、哈希链和回放包基础。
- `engine/edgefield.py`、`engine/parallel_universe.py`：灵域与候选宇宙关系原型。
- `doc/world_engine_evolution_principles.md`：A–E 演化分期、状态权威和领域概念。
- `engine_platforms/godot/`、UE5 对比端、SceneKit 预览：可作为后端/观察器实验样本。

关键缺口：规则仍以应用级流程为主；完整的跨 tick 持久自然演化、通用规则调度协议、空间局部变化传播、长期存储/迁移策略、与世界状态时间一致的观察/渲染协议、规模和性能指标尚未收敛。现有 Godot/UE5 一致性仅证明当前快照字段消费一致，不证明它们可承载目标 4D 呈现模型。

## 3. 架构决策原则

- **先定义 edgeWorld 4D 契约，再优先基于 UE5 发布版落实。** 发布版插件/适配层为默认路线；源码修改需发布版实测缺口触发并经主任务评审。
- 规则执行、持久世界存储、观察/呈现接口在架构上分层；它们可以位于 UE5 同一进程，但必须有稳定边界。
- UE5 发布版中经实测无法支撑契约的能力，可先由项目插件/适配层旁路或补足；只有替代路径失败且有证据时，才评估引擎源码改造，不能默认整套重写。
- 世界状态只有规则执行内核可以提交修改；任何 AI 或前端提案都必须通过规则验证。
- 规则调用由显式依赖和触发条件决定，不默认每个对象每帧执行所有规则。
- 所有可变结果都要有规则版本、输入因果、逻辑时间和可重放依据。
- 远距离/休眠区域可以采用降频或闭式结算，但语义上仍遵循同一套世界规则。
- 允许引擎先以可视化投影验证 4D 状态，不要求第一版即实现高保真几何、完整宇宙规模或多人服务。

## 4. 分阶段执行

估算以一名熟悉代码库的资深通用引擎开发者为基准，包含设计、实现与阶段验收，不含商业级美术生产。阶段有依赖，日历时间不能简单通过功能拆分并行压缩。规格阶段通过后重估运行时与渲染工作量。

## 5. 第一版范围约束

首版只证明引擎范式，避免同时追求“完美世界”：

- 一个有限但可扩展的世界分区；有限数量的实体。
- 一个持久逻辑时钟和四象周期映射；渲染帧不驱动世界时钟。
- 少量先天规则和一种玩家/NPC 外部变化。
- 至少一种局部传播机制和一种衰减/恢复机制。
- 确定性事件历史、读档续演与时间点回放。
- UE5 发布版上的 edgeWorld 状态观察器与呈现管线，优先以项目级 Runtime 插件和现有渲染组件实现；UE 场景树/Actor 不能天然等同于权威世界状态。引擎源码变更须由发布版契约差距证据触发。

64 宇宙全量模拟、无限实体的字面实现、完整生态涌现、多人服务器、商业级资产、所有平台同时支持均不属于首个切片。它们须以模块和规模测试逐步纳入，而不是预先承诺。

## 6. 核心验收问题

每阶段都回答并留存证据：

1. 世界状态由什么唯一标识，如何分区，哪些数据是权威持久状态，哪些是可重建缓存？
2. 时间如何推进；离线跨越大量时间时如何结算且保持规则语义？
3. 规则何时被调用，依赖如何解析，冲突如何确定性仲裁，失败如何回滚？
4. 变化如何定位影响对象/区域，如何限制传播并记录来源？
5. 如何保存规则版本和随机源，使旧世界可续算或明确迁移？
6. 渲染器查询的是当前状态、历史状态还是未来投影？查询是否纯读？
7. 怎样证明视角、帧率、UE 渲染线程调度不改变世界演化？
8. 目标硬件、世界范围、实体数、活跃比例、帧率、启动时间、存档寿命与在线人数是多少？
9. 是否需要向团队/发行版分发修改后的 UE 引擎二进制或源码？许可条款如何影响定价、开源与潜在交易？

## 7. 当前执行顺序

1. 本计划取代旧的客户端优先路线；保留旧文档作历史参考。当前决策是 UE5 发布版优先，源码改造仅是由实测契约缺口触发的后备方案。
2. 阶段 0 已完成提交基线与当前未提交改动审阅，并形成 UE5.8.3 发布版插件纵切方案；历史源码 5.8.2 构建记录不可替代发布版验证。
3. 阶段 1 以 `doc/phase1_4d_prototype_contract.md` 锁定最小原型契约，生产架构未决项另行保留；继续调整 `world_engine_evolution_principles.md` 中与本路线冲突的实现阶段表述。
4. 契约评审完成前，不扩张 Godot 游戏功能、不启动服务端或大规模内容制作；允许开展 UE5 发布版插件/Genesis 纵切验证和必要的接口小实验。
5. 阶段 2 在 UE5 发布版插件中从一条完整跨时间因果链开始实现；每阶段更新能力矩阵、发布版 API/平台差距、风险与估算。只有发布版方案满足不了已批准契约时，才提出源码改造评估。

### 8.3 许可初步核验（非法律意见）

截至本次核验，Epic 当前 EULA 区分产品运行时分发、引擎代码分发和 Engine Tools 分发；修改后的 Engine Code 只能按 EULA 允许的对象分发。面向一般被许可方的 Engine Tools 公开分发需走 Epic 指定 marketplace 或 UE GitHub Network fork 等渠道。符合 Royalty Product 定义的产品可能适用收入阈值后的版税；具体适用要看 edgeWorld 将卖游戏、工具、引擎还是授权服务分别判断。[当前 Unreal Engine EULA](https://www.unrealengine.com/eula/unreal)

这对潜在商业化意味着：可先用 UE 源码研究与内部开发，但若最终目标是独立销售 edgeWorld 4D 引擎/工具、对非 UE 用户授权，必须在架构与 IP 规划阶段向 Epic/律师确认许可路径。最稳妥的知识产权隔离方式仍是保留清晰的 edgeWorld 自研模块、UE 修改补丁、Epic 原始代码及第三方依赖清单。

### 8.4 阶段 0 门结论（2026-10-09 历史源码路线记录）

- edgeWorld 当前规则/快照/历史资产可支撑 4D 契约和状态语义研究。
- 本机 UE 5.8 安装源码足以完成静态架构勘察；项目层 UE5 原型曾编译运行。
- Genesis 物理层可以消费 edgeWorld 四象逻辑时序并返回随规则变化的状态；简单自由刚体可以保存检查点并跨进程续算，证明物理求解器可作为 4D 演化运行时的一类可插拔执行模块。
- UE 源码在本机成功编译、链接和部署，源码构建工具链可行；4D 引擎架构和 Renderer/Scene 改造仍没有被这个构建结果验证。
- 上述结论是在 v0.2 源码改造路线下形成。v0.3 已将路线改为 UE 5.8.3 发布版插件优先：下一项是批准/执行 `doc/phase1_4d_prototype_contract.md` 中的 Runtime 插件 + edgeWorld worker + Genesis adapter + 现有 Renderer 纵切；不得把旧源码编辑器启动作为路线前置，也不得在发布版缺口实测前进行 Renderer/Scene 源码深改。
