# H1f：默认线程同步候选的干净复测

状态：统筹审定，H1e 独立审查接受，PR #62 已集成 `b89c5f3`；本卡提交后发布实施。
父节点：V-HOME / UE 退出可靠性。H6B/H6C 仍等待本门。

## Plan

目标是检验 H1e 候选在无残留 Crash Reporter 的完整场景中是否继续有效，
并据此决定能否作为显式项目旁路供后续开发使用。默认线程根因和总体可靠性
不能由几个干净退出样本证明。固定基线为 H1e 经审查的集成提交，发布卡记录
准确 SHA；独立 worktree/分支，一任务一 PR。

所有运行使用同一编译产物、默认渲染线程、完整因果场景和真实 Genesis。
A 仅记录通知；B 额外启用 `-EWDiagPreflushViewport`。不使用 `-norenderthread`。
不改引擎、世界规则、GameMode、相机、HUD、光照或访客路径。

## Do

1. 先使注册幂等：同一 client 再次 Init 前移除旧 handle，补注册、重复初始化及
   销毁解绑检查。此项不阻塞 H1e 有限诊断集成，是本轮复测的前置修复；重新
   构建及运行生命周期测试，既有 H1e 运行不作为新 binary 的验收证据。
2. 独占 GPU，交错运行 A1/B1/A2/B2。每次使用独立状态目录，初始化后至少
   180 秒再按同一窗口关闭协议结束。实际进程退出前不得启动下一次。
3. 每次记录构建/二进制身份、真实 UE/Worker PID、初始化、有效 tick 0/1/2、
   首张可见画面及通知/flush/关窗日志；历史 0、H 和相机操作前后比对全部
   权威文件。调用成功与原生关窗时间分别记录。
4. 每次运行前后核对 UE/Worker/reporter。故障先归档 crash context/minidump，
   再仅终止该次精确匹配的 orphan/reporter，验证消失后继续；不全局杀进程。
   无法消除干扰时该样本无效，保留后重做。用户进程出现时停用 GPU 并报告。
5. B 两次成功后，另作两个 B 边界样本：一个在窗口调整大小/最小化恢复后
   关闭，一个从既有 B 状态目录恢复并以 CmdQ 退出。逐一记录原生事件及哈希，
   不把它们计作受控 A/B 重复；任一失败保留栈并撤回候选通过结论。

## Check

独立审查代码与真实日志，复算原始证据哈希。B 每次必须记录默认渲染线程、
正确游戏窗口、GameThread、非空 owner、flush 前后 owner 不变以及真实退出 0；
同时要求恢复状态相同、只读文件不变、无遗留进程。工具超时须核对实际进程，
不得直接归因 UE 故障。A 的成功或失败均保留，不能制造对照故障。

## Act

- 任一有效 B 失败：候选未通过，分析原生栈，只重开受影响路径。
- B 全部通过且独立审查接受：最多接受为有限显式项目旁路；再单独审查启动器
  接线与默认选择，不自动启用，不宣称普遍可靠或性能提升。
- 全局可靠性、PIE、多平台和生产验收保持开放；按实际证据更新 backlog，
  scoped commit/PR，报告完成程度及下一动作。失败证据不得删除。
