## Behavior and API

Only `scripts/universe_iteration/lifecycle.py`, its targeted test and this evidence directory are owned. Standard library only, no imports of the other I13 modules, authority or Genesis; import has no runtime effects. No runner, verifier, product or shared interface edits.

- `budget_guard(*, now, dispatch, session_start, stage, stage_start, ready_binding, expected_binding, live_processes, expected_processes, sample_monotonic, contamination=False, closing=False, tool_seconds=0, global_limit=1200)` returns `decision` (`allow`, `quit_due`, `stop`), reason and remaining/deadline fields. `allow` requires independently expected full ready binding, exact live identities and passive sample age ≤2s. A UI tool call is bounded to 10s and cannot cross stage, 360s interaction or reserved global close limit. Build/startup and closed sessions have no UI permit. Stop/quit_due do not perform input release, quit or cleanup: the unique CUA owner does that.
- `parse_ps_snapshot(raw)` preserves complete argv and ps start text; rejects malformed/duplicate PID rows. `same_process(a,b)` matches pid/start/argv, allowing PPID changes. `classify_processes(rows, known_owned, accepted_executable)` follows exact roots/descendants and previously observed exact identities; extra accepted-UE executable instances are contamination even if PPID1. Accepted executable comes from the frozen outer card, never gets executed here.
- `observe_once(raw_path)` runs only the fixed `/bin/ps -ww -axo pid=,ppid=,lstart=,command=` query with 1s timeout, exclusively writes original stdout and returns SHA-bound sample metadata. `record_observer(stop_event, directory, prefix='sample', on_sample=None)` runs independently of supervisor termination, at target 0.5s cadence, including a final sample after stop. Caller owns a dedicated observer thread/process, immutable metadata publication, error capture and the correct stop condition. This module never starts an observer process or controls another process.
- `interval_union_seconds(intervals)` separately counts merged process intervals. It cannot replace continuous global dispatch-to-seal wall time.
- `validate_ledger(ledger, *, expected_run_binding, expected_clock_id, expected_executable, expected_launchers, expected_session_bindings, expected_storage_root, expected_public_paths)` compares expected inputs supplied independently by R. Public references must be explicitly allowlisted and inside approved storage before any file read; never derive the production allowlist by scanning private deployment. Raw ps/hash/metadata are replayed, exact identities/intervals reconciled, observer boundary/inter-sample gaps checked, staged serial sessions and same-card normal completions required. Nonfinite/bool numeric fields, forced cleanup, unknown exit, stale samples, omitted extras and incomplete wait evidence never grant success. Stage budgets are 60/60/240/40/20, session 420, quit ≤360, waits/reap ≤400, global ≤1200 and storage ≤2GiB.

Validator statuses: `fail` for contradictory evidence; `inconclusive` for missing files/required evidence, observer gaps or absent complete sessions; `checks_complete_requires_review` only for structurally complete supplied originals. It never grants G-B2, raw authenticity or runtime readiness. Partial failed sessions may return fail; this does not suppress V or erase their evidence.

## Receipt adapters required from R

`wait_ref` points to JSON `{kind:"actual-parent-wait", observed:true, identity:{pid,ppid,start,argv}, parent_pid:INT, exit_code:0, monotonic:SECONDS}`. The wait must occur after the last live observation, within the conservatively charged interval. This is an adapter around actual pinned parent-wait evidence, not permission to synthesize a wait from ps absence. Every tracked process currently needs its actual wait receipt for structural completion; missing receipts remain inconclusive.

`completion_ref` uses existing supervisor completion fields: normal, forced_cleanup, remaining_owned, accepted_source, run_id, world_id, authority_root, session, ue_pid, launcher_wait_exit, ue_exit_code, card_sha256 and worker_exits. Worker records retain generation/return_code_available/reaped/trace_complete/normal stop/no hard kill/no operational failure checks. The two sessions must share card SHA and own distinct UE/worker PIDs. R still checks the adapter's card hash against actual authorization and correlates original traces; A does not issue cards.

`storage_snapshot_ref` points to JSON `{kind:"whole-storage", includes_all_attempts:true, storage_root:"ABS", monotonic:FINAL_END, files:[{path:"ABS",bytes:INT},...]}`. A enumerates only metadata beneath independently approved storage and requires the complete actual file/size set, including snapshot itself; no content read during storage enumeration. No private key directory may be inside that approved storage. Snapshot self-size can use the existing fixed-point accounting approach; the CPU replay demonstrates it. New files written after that snapshot invalidate it, so R must account final ledger/receipt files and republish a new final snapshot and time as needed. A does not rewrite snapshots, old evidence or completion markers.

## Actual validation and limitations

Command: `python3 -m unittest tests.test_universe_iteration_lifecycle -v` — **16 passed**. Full output: [cpu-tests.txt](cpu-tests.txt). Includes a complete two-session synthetic replay plus meaningful rejection cases: PID reuse, PPID1 extra instance, raw/hash tampering, process omission, wrong source/clock, stale process sample, stage budget, missing wait/session, forced cleanup/unknown exits, whole-storage omitted file, private reference rejected before reading, and global wall budget that cannot be replaced by a smaller interval union. Observer query is mocked: no live UE, solver, UI, child launch, signals or native tests were run.

During construction, one observer test exposed that a stop raised by its sample callback did not produce a subsequent final sample; implementation now does. A later allowlist preflight exposed duplicate Path validation in a replay; corrected. Final tests pass; neither failure was a runtime attempt.

No evidence establishes real UE timing, process identity provenance, native Shot feasibility, input/quit behavior or actual observer cadence under UE load. The independent observer and CUA owner must be scheduled together by R; overdue/missing samples cannot be repaired by interpolation. The current strict requirement for every tracked child's wait may expose unavailable build-tool wait evidence: R must obtain real evidence or remain no-go, not manufacture exits. GPU/main workspace/key material were untouched.
