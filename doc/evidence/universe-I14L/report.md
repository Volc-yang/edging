## Root integration API

1. `LegacyBackend(expected_runner_sha256=SHA64)` loads only the adjacent fixed `run_universe_slice_acceptance.py`, checks its file and digest; never loads a JSON-selected module/callback or launches during construction.
2. `validate_card(path, *, expected_card_sha256, expected_product_source, expected_tool_source, expected_manifest_sha256, backend, execute=False)` validates mode/owner metadata, exact approved R13 execute, expiry, independently supplied product/tool/runner/manifest pins, actual clean tool source, v2 allocation and reviewed runtime-capability originals. Returns a non-JSON-restorable `ValidatedCard`. This outer check is deliberately **not a substitute for the full legacy validation at step 4**.
3. `DispatchController(validated_card, backend=backend)` creates one exclusive persistent controller directory and starts the global clock; `start_observer()` runs the fixed passive ps query on an independent non-daemon thread, across both sessions. Sample metadata/raw and controller events are exclusively written and indexed in `public_refs`. Gaps >2s revoke further permits and invalidate a normal seal. This Python instance must remain alive; do not reconstruct it from JSON between CLI calls.
4. `begin_session('initialize'|'existing')` calls original `validate_run(inner_path, inner_hash, product_source, session, True)` before starting anything. All original owner/private pins, source cleanliness, lexical venv chain, RPATH/deployment checks remain. Backend compares original context/launcher hash/storage/UE/Python paths and all stage/resource mappings with the approved outer card. It then calls the original `supervise` on one live thread; the original supervisor owns actual Popen and wait until return. `SessionHandle.wait(timeout)` cannot infer exit from ps or serialized receipts. S2 requires original S1 normal completion plus independently supplied complete action result; no retries/third session.
5. `record_stage(stage)` advances build→startup→interaction→shutdown→seal in memory for permit control. These caller transitions **do not become final stage evidence**: the assembler uses original supervisor-events and actual supervisor return boundaries. `register_ready(binding, expected_binding=..., identities=..., verified_ready_ref=...)` binds root-verified status/observation/projection originals to actual identities. Root still authenticates parser provenance.
6. `permit(action_id, timeout, log_path=..., log_offset=...)` requires a pinned manifest action, exact current host/worker identities, fresh ≤2s passive sample, no extra UE instance, current UE log tail/inode/hash, ≤10s and sufficient stage/session/global time. `consume_permit` checks expiry, replay, current process sample and log identity/prefix; closing/stopped sessions revoke all permits. No UI is executed by this code. `request_quit(reason)` / `ack_quit(raw_cua_ref)` instruct the unique CUA owner; an acknowledgement is not proof of exit. If the owner does not quit, the original supervisor's bounded timeout/exact cleanup remains failure, never normal completion.
7. `collect_session(action_check_ref=...)` reads `SessionHandle.wait()` and original published completion, exact original stdout parent-wait line, supervisor-events, worker-exit metadata/bin. It writes `controller_output/session-<name>/waits/{launcher,ue,worker}.json`, each pointing to actual originals. Wrapper time is explicitly `controller-read-upper-bound`, not an exact exit instant. Core identities must appear uniquely in independent samples and agree with validated ready PID. Native decimal FString generation is normalized only in a new v2 completion adapter; original completion/trace bytes remain unchanged. Missing signals are recorded as assembly inconclusive; nothing is invented.
8. Before final policy publication, call `stop_after_quiescence(expected_owned=...)` using exact known roots, only after the supervisor is done. It reconstructs historical owned descendants (including reparented ones), requires the last sample quiet and takes a final independent sample. No UI binding may be touched after closing. Root forms the independent expected v2 policy including the explicit public references generated by this controller and the known future `ledger-v2.json` / `storage-snapshot.json` paths; never derive the public list by scanning private deployment. Calling finalize directly is also supported when those final sample paths are preapproved.
9. `finalize_run(expected_policy=...)` builds process intervals/roles, session stages, wait refs, and a whole-storage metadata snapshot. It includes snapshot and ledger bytes by fixed-point iteration, exclusively publishes both, then calls `audit_finalized_ledger` from the still-live owner. Actual publication/audit must finish before explicit charged-end (2s conservative reserve) and all observed/observer/actual seal relations are checked. The returned `actual_finalized_monotonic` is measured after validation; writing more files later requires a new explicit accounting cycle and cannot reuse this snapshot. No root stdout or later files may be silently excluded from an actual resource card's chosen whole-storage boundary.

## V2 evidence semantics

Core roles derive first from externally expected launcher/UE/worker IDs; role labels cannot reclassify them as build. All three require actual exit0 parent-wait evidence and same-card normal completion; worker EOF/reap/trace flags remain strict. Build descendants need same-sample ancestry within the actual build phase, pinned launcher source containing the genuine PIPESTATUS[0] assignment, and exact original `[launcher] build_exit_code=0` line range. Without a real individual wait, exit_status must remain null. Unknown core exits, forced cleanup, missing core, omitted process, spoofed ancestry, gap, extra UE or storage overflow cannot grant success.

Snapshot time and actual seal boundary are separate from conservative charged-end. `actual_finalized_monotonic` missing → inconclusive; crossing charged-end → fail. Successful validation is only `checks_complete_requires_review`, never G-B2/runtime authenticity. Root/V still independently authenticate card/source/real parent wait/proof origins and all action/capture evidence.
