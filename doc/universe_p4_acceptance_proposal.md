## 总节点 P4 的 PDCA

**Plan。** 固定构建、输入、目标机和检查脚本，建立原始证据索引；先验证采证工具能区分有效信号、错误和缺失，再由独立人员执行子检查及整合路径。UE 发布版与插件是默认路线；验收失败先定位最小依赖，不直接推导引擎源码改造。

**Do。** 本轮交付验收矩阵、证据契约、阈值冻结表和只读调查结论。未来执行轮只在独立项目/状态目录与已分配资源中采证；任何注入或重启只针对验收实例。

**Check。** 提案检查为：所有要求有对应节点、每节点有 PDCA/证据/责任人/结果、依赖无环、提案与实测分开。运行总门要求 P4.1–P4.8 必要项及整合路径均 pass；单模块通过不能替代端到端结果。

**Act。** 本轮请求统筹审查并冻结开放决策；后续 fail 返回最小责任节点，inconclusive 返回缺证节点。仅改变一项原因后重测受影响节点与下游整合；保留旧运行和失败证据，不倒改阈值。

## 统一结果和证据契约（P4.1，parent=P4）

**Plan。** 依赖 U0/U7；独立检查人先确认身份完整性。每个 run 使用唯一 ID，关联 check ID、阈值版本、执行者、开始/结束 UTC 与单调时间、退出码、超时、目标进程 PID 和实例 ID。结果含事实、假设、未知项三个字段。

**Do。** 提议未来证据包分为 `identity.json`、`raw/`、`index.jsonl`、`summary.json` 和 `review.md`。原始文件写完即封存，后续追加索引版本，不覆盖文件。Git 存小型索引与报告，大文件进入专属归档，记录可访问位置及保留策略。

身份至少包括：完整源码 SHA、干净状态或补丁及其 hash、UE 版本/CL、target/config、可执行文件和插件二进制 hash、构建完整日志与退出码、OS/硬件/驱动/电源模式、Genesis/Python/依赖版本、启动参数、地图/GameMode、分辨率/画质/动态分辨率/VSync/帧率上限、世界/载具/化身 ID、seed、初态原始与规范化 hash、规则/协议/AI 模型与生成输入版本、checkpoint/资产清单 hash。仅 seed 相同不能证明世界输入相同。

每个 artifact 索引字段建议为：`run_id, check_id, action_id, relative_path, storage_uri, sha256, bytes, started_at, ended_at, tick, revision, watermark, producer, completeness`。轨迹/输入/录像/日志/trace 用相同 action ID 和时间标记对齐，并记录时钟偏移与误差；不得只凭文件名配对。报告定位到原始文件、行号/样本范围/录像时间码。

**Check。** 校验所有原始文件可读、大小和 SHA-256 匹配；从索引反查构建与动作；核对日志头尾、协议帧数、trace 区间、录像时间及异常退出是否完整。校验工具未来须用删除文件、篡改一字节、截断日志、错配 run ID 的独立样本验证。当前未实现或运行该工具。

**Act / 评价。** `pass`：已冻结判据的完整证据满足预期；`fail`：有效证据明确违反判据；`inconclusive`：原始文件缺失、身份不明、采样无信号、未冻结阈值或未执行。已观测的明确违规即使另有缺证仍保留 fail，不能降为 inconclusive。总门有必要项 fail 则 fail；无 fail 但有必要项 inconclusive 则 inconclusive；仅全部 pass 才 pass。探索项或不适用项须在运行前冻结范围，运行后不能移出必要项。

## 权威只读与帧率隔离（P4.2，parent=P4）

**Plan。** 依赖 U1/U4；检查人选择同一 checkpoint 的独立副本，冻结逻辑时钟并隔离后台写者；若世界采用持续调度，则使用同命令/调度的配对对照，比较相同逻辑水位，不能要求持续演化世界跨墙钟时间 head 静止。

**Do。** 分别执行相机移动、画质切换、帧率上限变化、暂停/恢复、显隐、同水位重复 Observe、历史查询和错误 watermark 查询。每次动作有前后 manifest 原始字节、state/event head、tick/revision/watermark、事件数、随机游标和完整请求响应；写入命令日志证明该区间没有获准推进。帧率试验另对同一输入命令序列重放并比较权威轨迹。

**Check。** 冻结态中上述权威字段及 manifest 字节必须完全一致；错误水位须拒绝且不写入。缓存/截图等呈现文件允许变化但须不在权威清单。帧率改变不得增加权威步数或改变同逻辑步轨迹（数值容差由 P4.3 冻结）。加入一次明确 Advance 作为正对照，证明探针能看到真实状态变化；负对照在隔离 fixture 中验证，不改产品绕过权限。

**Act / 评价。** 变化可归因于未授权呈现动作则 fail，返回 U1/U4；区间混入合法写者则 inconclusive，重采窄区间。相同头尾 hash 只是端点证据，必须结合完整命令/事件记录排除中途改写再恢复。现有证据只支持部分相机/观察操作，完整矩阵尚未运行。

## 载具物理、接地和恢复（P4.3，parent=P4）

**Plan。** 依赖 U1/U3/P0 物理契约；采用米/秒/千克与 UE cm 转换表，冻结坐标轴、重力、碰撞形状、地形碰撞版本、固定步长、solver/substep、输入采样和接地判据。独立 oracle 包含解析自由落体/匀速段及受控平面接触，不只与实现自己的输出比较。

**Do。** 保存逐步逻辑 tick、输入 ID、位置/姿态、线/角速度、接触点/法向/冲量、穿透深度、载具和乘员身份、物理候选与权威提交 ID。覆盖接近、下降、接地、稳定停驻、出舱、再登载、起飞；保留拒绝非法状态迁移、重复提交和超限输入的案例。独立验收实例从下降前及接地后 checkpoint 重启各一次。

**Check。** 核对输入→物理候选→提交→画面时间关系，防止 UE 视觉插值被误当权威轨迹。分析位置/速度/姿态误差、接地事件顺序、最大穿透、停驻漂移、接地抖动、恢复前后连续性；同构建同机固定命令重放，对跨硬件误差另立判据。不能把单刚体原型的成功迁移为载具门通过。

**Act / 评价。** 违反冻结权限/事件顺序直接 fail；物理数值仅在对应容差已冻结且采样有效时判 pass/fail，容差待决则 inconclusive。失败分别回到单位、模型、积分或同步节点；当前载具全链路未运行。

## 可玩路径和因果重访（P4.5，parent=P4）

**Plan。** 依赖 U1–U5/U7；一名非实现者实际操控一次，再由独立脚本重演一次。固定路线、输入设备、成功事件、各步骤超时、允许的控制辅助；自动录像或相机轨道本身不能证明可玩。

**Do / Check。** 下表每步保存输入、响应、权威事件、轨迹及录像时间码，检查人逐步确认，任一步不能依靠开发者控制台跳过。首次失败即保存现场和 checkpoint。

| 顺序 | 人类动作 | 必要证据与成功条件 |
| --- | --- | --- |
| 1 | 接近并选择登陆点 | 操作者、化身、载具 ID 清晰；选点权限及目标坐标有效 |
| 2 | 下降与接地 | 输入可控、轨迹连续；获准接地事件先于出舱；碰撞满足 P4.3 |
| 3 | 出舱与探索 | 控制权从载具转到同一化身；脚步碰撞/地面位置有效；到达指定交互点 |
| 4 | 执行一次世界交互 | 命令获准且恰好提交一次；拒绝非法交互留拒绝理由；AI 提案含来源并经规则验证 |
| 5 | 登载、离开 | 化身/载具/区域身份保持；离开事件和存档水位有证据 |
| 6 | 离线演化与进程重启 | 按冻结的逻辑时间/调度规则结算；保存输入环境、规则版本、事件链与 checkpoint；重启后恢复正确水位 |
| 7 | 重访和对照 | 回到相同区域和持续身份；至少一个获准对象发生可解释变化；能精确查询离开前历史；历史查询不改当前 head |

离线是玩家离开/客户端断开还是权威进程停机，须 P0 冻结；停机后的补算必须有显式逻辑区间与幂等键。不得用墙钟等待或视觉换皮推断演化已发生。将离开存档离线重放到重访水位，核对状态/事件摘要及规则原因；单独保留物理浮点容差与权威序列化一致性判据。

**Act / 评价。** 权限错误、身份丢失、重复提交、历史被改写或冻结脚本无法完成均 fail；缺少载具/交互/离线结算实现或采证不完整为 inconclusive，并明确缺失能力。分别评可演示、可玩、可恢复和演化可信，不将一个维度的通过扩散为总通过。当前整条路径未执行。

## 帧时间、加载与资源（P4.6，parent=P4）

**Plan。** 依赖 U4/U5/U7；提议首个基准固定 Apple M4 Pro/Metal，但确切内存、OS、分辨率、质量和发布形态由 U0 冻结。Editor/Standalone/打包结果分别记录。稳态提议预热 30 秒、每路段采样 120 秒、重复 3 次；加载与重访冷/热缓存分开，预热不得掩盖首次进入停顿。

**Do。** 使用独立验收实例的 Unreal Insights 或经验证的 CSV profiler，保留完整 trace/CSV、会话配置和导出命令。首先验证 GPU 时间通道实际有样本；录 CPU Frame/Game/Render/RHI 与 GPU 时间、内存、流送和加载标记。路线、视角、演化水位与分辨率必须固定，记录其他 UE/Worker 竞争负载。

**Check。** 对每段分别报告有效样本数、缺失比例、p50/p95/p99、最大帧时间、超预算帧比例；CPU/GPU 分列，给出排序及 percentile 算法，不用平均 FPS 倒数代替分位数。记录加载/存档/恢复延迟与峰值内存，统计中保留异常段；若需排除须事先冻结规则并同时报告原始分布。GPU 缺样只将 GPU 项判 inconclusive，CPU 结果仍可独立报告。

**Act / 评价。** trace 有效且满足冻结预算才 pass；明确超预算为 fail；只有帧率上限或 stat 截图则性能 inconclusive。热降频/背景负载不明先复核环境而非调整门槛。当前没有可信 CPU/GPU trace。

## 证据保全与总门复核（P4.8，parent=P4）

**Plan。** 依赖 P4.1–P4.7；由第二位独立审查人验证索引及结论。提议每失败检查最多 2 次补采、单个全链路 run 最多 30 分钟、每轮原始证据 10 GiB，最终预算由统筹冻结。

**Do。** 保留失败 run 和第一次成功 run，各自独立编号。重启/故障注入仅限验收自有 worker，记录 PID、状态目录及故障边界；不停止用户 UE，不复用其控制文件。证据量/超时到界即正常停止自有采集并封存；不得删除原始材料腾空间后继续宣称完整。

**Check。** 校验 checkpoint 重启和故障边界恢复；验证完整事件链、manifest 和重复命令幂等；抽样从报告定位原始视频/轨迹/trace，并复算摘要和性能分位数。子节点通过后再执行一次同构建/seed/规则的整合路径。若中途换构建，整合 run 重新编号并重新运行受影响路径。

**Act / 评价。** 总报告列必要项结果、版本、缺证、失败 owner 和下一轮输入；资源上限或外部资源冲突导致缺证为 inconclusive，已确认产品崩溃/损坏为 fail。扩大区域、多人、跨 GPU 或发行形态必须新建验收节点，单区通过不证明可扩展宇宙完成。
