| 阶段 | 执行与裁决 |
| --- | --- |
| Plan | 从总计划中取拓扑 ready 的节点，确定输入 commit、接口版本、owner、写入路径、独占资源、完成门、审查者和预算。检查是否与运行中的任务冲突。 |

## 发布与反馈协议

1. **统筹发布卡。** 用 F0 最小字段，加 `execution_kind = subagent | user_visible_chat`、`chat_id/agent_id`、`resource_lock`、`ready_condition` 和明确禁止路径。新对话只在用户要求时创建；创建后检查其真实运行状态，不能以“返回 threadId”当作已开工。
2. **执行者确认。** 回报 worktree/branch/base 的实际状态、输入是否存在、拥有的文件与当前阻塞。若准备过程异步创建 worktree，统筹先检查该树是否干净、是否已有提交；不能同时再派另一个 owner 写同一树。
3. **任务交付。** 执行者给 PR、commit、实际 Check、原始证据索引、未测项、Act 建议和 worktree 状态。只读研究和实现 PR 独立评审；提交本身不等于通过。
4. **统筹审查与集成。** 先看精确 diff/CI/范围和接口，再合并。合并后运行父级集成 Check；登记合并提交和每门结果。失败可要求原 owner 返工或给新 owner 新节点，不能把旧失败记录改为通过。
5. **收尾和下轮。** 清理仅已审查合并且干净的任务 worktree。保留未合并、撤回但有独立提交、或仍有用户改动的树并写原因。主会话精简上下文：目标/决策、DAG ready 队列、任务/PR/门状态、风险、下一动作；提交一次统筹检查点。

## 新对话协调规则

- 本项目真实 Git 根为 `/Users/yangacan/edgeWorld/edge-world`；外层 `/Users/yangacan/edgeWorld` 不是 Git 仓库。应用项目仍指外层时，新对话提示必须明确内层根和准确分支/路径。若应用未把该根识别为 Git 项目，不依赖其自动 worktree 机制；由任务在内层仓库按已登记路径创建，先检查 collision。
- 给独立对话的提示只包含当前任务卡及链接，不复制长历史。对话完成需回报结构化结果；主会话用状态快照跟踪，不能让等待中的旧对话继续按被撤回的卡写文件。
- 新对话创建可能先 `systemError` 后异步重试，或先建树后执行。主会话在新任务发布、范围纠正和清理前都检查真实对话状态、worktree `HEAD/status`、PR diff。任务撤回时消息通知旧对话；其既有提交保留但不并入新范围。
- 当前两条旧对话 P0/P4 在首次 `gpt-5.5` 不支持错误后异步执行了旧任务，创建 PR #21/#20 并与 F0/F1 共享了旧 worktree。两 PR 已关闭；干净替代 PR #22/#23 已合并。旧 worktree 含未合并的撤回历史，保留而不强制清理。新对话再派发前必须解决应用默认模型与当前账号不兼容的问题，并使用修订任务卡。

## 依赖与资源的路由检查

发布一个 `ready` 节点前，统筹逐项核对：`depends_on` 的必要门是否已接受；共享接口版本是否相同；写路径是否无重叠；UE/Worker/设备/状态目录是否独立；目标分支和 base commit 是否可定位；独立 reviewer 是否可用。检查形成发布记录，不靠 agent 自己猜测。

同一轮可并行只读方案；写任务若读未冻结接口只能报告假设，不可实现依赖代码。产品目标或接口改变时，先计算受影响下游，暂停这些节点，完成独立节点继续保留。F0/F1 的字段和本协议构成下一轮启动清单。
