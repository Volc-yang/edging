# Seed→Tree × Genesis：下一版 PDCA 方案树

状态：2026-11-01，v0.1 设计方案；基线 `8a069fa`。用户已选择 Seed→Tree 场景，并要求 Genesis 物理为必需路径。本文先定义可派的设计任务与接口裁决门；未批准具体植物规律或物理行为，也未宣称旧 Seed→Tree v0.1 包含 Genesis。

## 版本根节点 V-STG

目标：从稳定身份的种子出发，按显式逻辑时间生成可观察的树；同一权威因果链中包含一次可追溯的 Genesis 物理结果；UE5 发布版渲染至少种子、幼苗和成树的指定历史切片。重复命令、重启恢复与纯读呈现须有可复查证据。AI 提案和载具登陆留作后续版本，不是本版必需门。

**边界冲突：**[Seed→Tree v0.1](seed_tree_4d_render_slice_contract.md)的树 worker 不调用 Genesis，旧[阶段 1 契约](phase1_4d_prototype_contract.md)仅有单自由刚体。两条旧纵切不能简单并排运行就声称一个权威世界。G1 必须先冻结物理结果如何进入同一 tick 的候选状态、事件与提交边界，及其失败时不提交的规则。物理对象/量和与树演化的因果关系需要单独产品/技术裁决。

```text
V-STG 范围和质量门
├─ S0 场景/物理语义与 G0 阈值裁决 ─────────────┐
├─ S1 共享状态和 Genesis 接口设计 ────────────┼─ S4 契约 v0.2 冻结
├─ S2 UE 呈现与输入/只读检查设计 ──────────────┤           │
└─ S3 证据、性能与独立验收设计 ────────────────┘           ▼
                                         G2a/b/c 实现 → G3 集成 → G4 独立验收 → G5 复盘
```

S1/S2/S3 可并行提交**设计提案**，写文件互不重叠；S4 由统筹对齐字段、时序、误差与门后发布实现卡。G2 实现不得根据未批准的物理语义或视觉/性能阈值抢先定案。

## 迭代检查与停止条件

设计卡各自经独立 PR 和 CI 审查；PR 合并仅说明设计交付已集成。S4 需单独验收其接口与门，不把三份提案自动提升为已批准契约。运行阶段至少包含树演化、Genesis 物理候选、UE 只读呈现、重启恢复和独立复核；实测失败保留原始证据并只重开受影响叶卡。若目标机/性能/物理容差尚未冻结，G4 不能判产品门通过。
