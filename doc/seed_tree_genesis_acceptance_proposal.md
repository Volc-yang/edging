# S3：Seed→Tree × Genesis 独立验收与证据方案

状态：2026-11-01，v0.2 **设计提案**；基线 `ac5ec2f`；父节点 `V-STG/S3`。用户已选 Seed→Tree 场景且 Genesis 为必需路径，并明确 seed/tree 是抽象初态与因果发展结构，**并非植物实体**。本文规定怎样验收下一版，不设定未经批准的状态规律、物理行为、误差或画质。旧 [植物树契约 v0.1](seed_tree_4d_render_slice_contract.md)明确不接 Genesis，[阶段 1 物理契约](phase1_4d_prototype_contract.md)仅为单刚体实验；两组旧证据只能作技术参考，不能合并计算为新版本端到端通过。

## Plan：冻结输入与验收身份

S4 新契约冻结之前，统筹须记录：Genesis 候选作用于哪个稳定实体/状态字段、何种可观察物理量、候选如何成为抽象结构发展的一条因果输入、因果节点/边的身份与拓扑约束、单位/坐标、单 tick 内顺序和失败后的提交边界。G0 还须冻结目标机、UE build、分辨率、场景路线、视觉参考、容差、超时、性能/内存阈值、运行次数和预算。本方案允许先设计检查与试采，**缺阈值时只报告实测，不判产品门通过**。AI 提案与载具登陆不列本版本必需项。

每个 `run_id` 在隔离目录中保存以下身份，首次运行前写入只追加 manifest，后续变更产生新 run/version，不覆盖旧证据：

| 类别 | 必填身份与原始文件 |
| --- | --- |
| 源码/构建 | 精确 Git SHA 与脏改动标记、S4 契约/规则/投影版本、UE 5.8.3 build/CL、插件构建配置与完整构建日志/退出码 |
| 世界/物理 | `world_id`、seed、抽象 seed/发展结构/物理参与者稳定 ID、初态 SHA256、版本化因果输入序列、Genesis 包版本、后端/设备、dt、步数、重力/材质等实际配置与其 SHA256；若 S4 未批准配置则标 `provisional` |
| 进程/执行 | 启动 argv、运行环境、隔离 state directory、请求脚本版本、每条 JSONL 原始请求/响应与时间戳、worker/UE stderr/stdout、关闭与重启退出码 |
| 权威/因果 | 每个检查点的 tick/revision、水位、state/event/head、因果图节点/边摘要与物理候选/已提交摘要、持久文件 SHA256；失败请求的提交前后摘要 |
| 呈现/性能 | 固定相机/路线、显示与实际渲染分辨率、Metal RHI、各历史切片原始图或录像；CPU/GPU 未过滤 trace、工具版本、采样时间窗/样本数、统计脚本与结果 |
| 审查/留存 | G0 门版本、期望与实际、检查者、原始文件路径和 SHA256、可达性/留存期限、资产来源与许可清单、成本账 |

原始大文件放 DevSSD 的独立 `runs/<run_id>/raw/`，Git 只保存小型索引与裁决报告。若原始文件只在本机，报告必须写明跨机器不可复查限制；不能仅以截图缩略图或日志摘要取代原始数据。[GQ 规范](pdca_gq_evidence_baseline.md)的 CPU/GPU 信号短探针先于正式性能门。

## Do：分层检查序列

先由实现 owner 做固定输入自检，再由非实现 owner 在**准确的 G3 集成提交**独立运行；两次记录不能互相替代。独立 reviewer 的顺序：

1. 核对 S4 契约、G0 门、构建/依赖/资产身份和 state directory 隔离。启动前记录初态文件哈希与状态目录边界；等待 worker 初始化完成后设稳定检查点，避免把首次初始化写文件误判为 `status` 写入。旧 [G1 探针](pdca_g1_runtime_probe_report.md)的首次 `status` 正有此归因限制。
2. 从全新状态目录执行 `status → observe(抽象初态 tick 0) → 显式 advance → observe(中间态) → 继续显式 advance → observe(发展结构态)`，逐条留存请求/响应、抽象状态/结构与 Genesis 候选/提交摘要、因果节点/边及事件和持久文件哈希。核对每条已提交因果边的源/目标节点存在、稳定 ID 与 tick/revision 对应、无无主物理候选；Genesis 候选按 S4 冻结的映射确实进入后态计算或得到显式拒绝。只使用 S4 冻结的 tick/环境/物理 fixture；本方案不指定演化规律、物理轨迹数值或结构外形。
3. 对相同 `command_id`/相同输入重放，检查响应相等且无二次 Genesis 步进或新提交；同 ID 不同输入、过期 revision、错误 world/水位、缺历史以及注入的 Genesis 失败必须按冻结错误表拒绝，并验证没有成功提交。错误注入必须是有界且不破坏其他 run。
4. 从同一固定输入分别运行不间断轨迹与检查点关闭/重启轨迹；逐 tick 比对抽象状态/结构、Genesis 候选、因果图、事件与权威摘要。重复当前和历史观察，前后比对稳定状态文件与 head；历史缺失不得回退当前。比较 Genesis 配置/设备是否相同；跨设备等价性另立门。
5. UE 5.8.3 发布版真实 Metal 下由已验证的观察结果投影 抽象初态/中间态/发展结构态三个指定 tick/watermark，存原图、相机位姿、响应 ID 与 state hash。对相机移动、帧率设置、暂停恢复、显隐、重复 Observe 和键盘输入逐项记录命令/画面及权威摘要；只有显式 Advance 可改变权威状态。错误/错身份响应不得更新 Actor。NullRHI 与构建结果只算结构检查。
6. 有独占 UE/GPU 窗口时先运行 10–20 秒 CPU/GPU 同窗信号短探针；信号有效后按 G0 冻结的路线、预热、采样窗和重复次数正式采集。保存全量 trace，逐 run 报有效样本比例、CPU/GPU p50/p95/max、内存和异常；不得剔除异常帧来改善统计。核对素材来源/授权与执行预算。

## Check：独立验收矩阵

| 门 | 可区分成功/失败的方法与证据 | 设计时状态 |
| --- | --- | --- |
| STG-C 契约/构建 | S4 版本和 G0 必需项映射至唯一 owner；干净环境构建/启动及完整日志，目标机与超时按冻结值 | `planned`；S4 尚未冻结 |
| STG-A 权威与物理因果 | 同一 world/tick/revision 中 Genesis 候选被权威验证后才提交；抽象状态、Genesis 候选和因果节点/边能追到同一命令与提交；Genesis 候选须按 S4 冻结的映射影响后态或明确拒绝，不能只在日志里孤立出现；失败无提交 | `planned`；物理对象和数值待 S0/S1 |
| STG-D 确定性/幂等/恢复 | 固定同机同版本输入，逐 tick 抽象状态/因果图/物理/事件摘要重演与重启对照；重复 command 不二次步进，负例拒绝且持久摘要不变 | `planned`；旧植物树和单刚体各自通过不算联合通过 |
| STG-O 历史/呈现只读 | 抽象初态/中间态/发展结构态精确切片与水位；所有逐项观察及相机/暂停/显隐前后 state/event/head 与持久文件摘要一致；错身份不呈现 | `planned`；旧局部证据可作对照，不代替新集成检查 |
| STG-V Metal 可见/可操作 | 固定相机三种抽象状态真实 Metal 原图，UE 输入动作日志和独立视觉评审；参照 G0 冻结标准区分技术可辨与写实质量 | `planned`；无批准写实标准不得判写实通过 |
| STG-P 性能/资源 | CPU/GPU 同窗有效 trace、内存/负载和冻结方法/阈值逐 run 比对；FPS 上限回读不能代替帧时间 | `planned`；当前 GQ 尚无实际 GPU 样本 |
| STG-E 证据/来源/成本 | reviewer 抽样重算 SHA256、状态摘要和统计，核对原始可达、资产许可与预算 | `planned`；准确留存/预算待定 |

每门结论用 `pass | fail | inconclusive | planned`；`fail` 指已执行有效检查且违反预先冻结阈值，`inconclusive` 指未执行、缺样、身份不明或无法归因。只准由统筹记录明示豁免及剩余影响，实施 owner 不得改门值自证通过。父级 V-STG 的通过须所有本版必需门通过，并有 G3 集成及 G4 非实现 owner 复查；PR 合并和测试自检不是父级通过。

## Act：缺口处理与下一卡

接口/因果链失败回到 S1/S4 与相应 G2a/b；画面或输入失败回到 S2/G2c；GPU 信号缺失先重做 GQ 短探针；阈值/视觉参考未冻结回到 S0。保留每次失败的原始 run 和门版本，仅重开受影响节点。当前 S3 交付是**验收设计**，没有执行新 UE、Genesis 或性能采样；下一卡由统筹结合 S1/S2 与 G0 裁决形成 S4 契约及具体可执行 fixture。
