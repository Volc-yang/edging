# 第一轮 PDCA：初始混沌宇宙规划

日期：2026-10-27
状态：P（规划）完成，D/C/A 待执行；本文是待审的第一轮实现提案，不把世界规则参数视为已批准契约。
基线：`feature/edge-world` 的 `d6298e3`；规划分支 `codex/chaos-universe-pdca-plan`。

## 1. 用户确认的起源设定

第一章从混沌世界开始。混沌不是空无或只有噪声：城市、蛮荒、原野、森林、海洋、河泽已经共同组成近乎完美的“天地玄黄，宇宙洪荒”。世界形态可以完整，万物之灵的独立身份、关系和命运尚未分化。4D 引擎推进“一生二，二生三，三生万物”，使世界整体与其中的事物逐步成为可追踪的世界之灵；玩家的世界内化身也属于世界之灵。世界的空间表现不预设方块。

“未知、随机、无主、无规律”描述混沌世界内尚未确立、尚不可归属的秩序，不意味着存档没有单一权威写者，也不意味着引擎可产生无法记录的随机变化。混沌起源的生成种子、规则版本、随机流和提交事件必须可保存、查询与重放。

## 2. 第一轮目标与范围

**目标：**形成一个可进入、可观察、可保存的初始混沌宇宙，并在同一权威世界状态上演示首次“分化”事件。玩家能先看到丰盛而连续的世界，再看到世界从整体状态产生第一条可解释的灵域边界。

**本轮最小纵切：**一片连续地理区域，包含城市、蛮荒、原野、森林、海洋与河泽六类场所，以及贯通陆地与海洋的水系。它是完整宇宙的可审查样本，不把六类场所等同于六块固定网格，也不声称已制作完整星球。可沿用现有 8×8 卦域图册作为索引或观察窗口，但不得将已分配的卦域法则倒称为混沌世界已显现的本体规律。

**本轮停止点：**验证“混沌 → 一”的第一条状态转移。二生三、三生万物的规则树在此轮定义候选接口和后续阶段门，不在首轮同时实现全生态、城市社会和玩家创生系统。

## 3. 初始世界状态

| 层 | tick 0 应有的内容 | 本轮须明确的边界 |
| --- | --- | --- |
| 世界整体 | 一个稳定 `world_id`、起源 seed、混沌纪元、逻辑时间和版本化生成清单 | 世界已有形态；尚无已提交的独立灵域谱系 |
| 地理 | 城市与自然区域在同一连续空间中相接；陆地高程、水系流向、海岸和河泽相容 | 几何可由 UE5 生成或资产表达；空间形式不决定权威状态 |
| 生态与文明 | 森林、原野、蛮荒和城市有可辨认的外观与分布；海洋、河流、河泽连通 | 初态可有生物与居民的可见表现；其灵域身份/社会规则在后续分化门中界定 |
| 潜势 | 可记录的环境、资源、扰动和关系候选数据 | 不把视觉随机性直接当演化规则；不预先赋予万物完整的灵域谱系 |
| 玩家 | 外部操作者可观察初态；世界内化身作为待分化的世界之灵候选 | 账号/输入会话与世界内身份分开；玩家行动经权威规则批准后才进入因果历史 |

“近乎完美”的第一轮操作定义：六类场所各自可辨认，地理连接可信，进入城市到河泽再到海洋的观察路径连续，静止观察不会使权威世界跳变。它是可测的视觉/空间质量门，尚非生物或社会模拟真实性声明。

## 4. 起源状态机草案

```text
CHAOS：万象俱在；世界整体有身份，独立灵域未提交
  └─ 起源事件 O1，记录触发条件、随机流位置和前态摘要
ONE：世界整体之灵成为可观察的统一边界
  └─ 后续候选：分化为内/外、阴/阳等有界的双势
TWO：两势并存并发生关系
  └─ 后续候选：形成可持续的作用与反馈
THREE：关系可产生新的独立起源
  └─ 后续候选：树、河、城市、居民、玩家化身等灵域谱系
MANY：万物之灵各有身份、规则引用、关系和历史
```

`ONE/TWO/THREE/MANY` 是规划用阶段名。哲学对应、触发阈值、玩家在何阶段取得世界内身份仍需在后续 PDCA 中审定。初始城市和居民可见，与其独立灵域身份何时确立是两件事；当前文档不能替后者作最终决定。

第一条 `O1` 提交至少应绑定 `world_id`、逻辑 tick、规则/Schema 版本、生成 seed、随机流位置、输入与触发来源、前后状态摘要、事件 ID 和因果原因。观察查询绑定固定 tick/watermark，UE5 仅呈现已提交样本。此边界沿用阶段 1 原型契约的单写者、显式推进、只读观察和可恢复原则。


### 任务边界

| 任务 | 交付物与文件所有权建议 | 验收证据 |
| --- | --- | --- |
| P0 主任务 | 独立起源契约/ADR；确定数据字段和首轮场景边界。不可与未完成的 Seed→Tree PIE 工作共改其状态目录。 | 设定、权威状态、随机性和 UE 观察职责无矛盾；评审记录 |
| D1 世界数据 | 新的 chaos world manifest、生成器与场所拓扑；只拥有新命名的生成/数据文件 | 同 seed/版本生成相同清单；六类场所存在且水系连通 |
| D2 起源规则 | 独立的起源规则模块、事件/快照协议；不改现有树/Genesis worker 协议 | 只显式推进 O1；重复命令幂等；重启重放摘要一致 |
| D3 UE 场景 | 独立的 Host 场景投影/配置；优先使用 UE5 发布版和项目插件 | 真实 RHI 画面能辨认六类场所和连续观察路径；帧率/视角不写权威状态 |
| C1/C2 统筹验收 | 事件、状态摘要、截图/日志和差异结论 | 记录实际通过与失败项，不以构建或概念图代替阶段门 |

共享 Schema 必须先由 P0 冻结。D1/D2 在 Schema 冻结后可并行；D3 可先探索资产和场景，但状态接线须等待 D1/D2 接口。真正需要编写文件的任务各用独立 worktree/分支。现有 PIE 纵切仍在进行中，本轮不改变其 worktree、证据或未提交内容。

## 6. PDCA 检查与调整

**Plan（本轮）：**确认初态设定、P0 契约、任务边界和验收样本；由主任务评审本方案树后发布实现任务。

**Do：**先产出权威 tick 0 数据，再实现 O1，最后让 UE5 呈现两种固定状态。不得让 UE 的 Game/Render Tick 自动推进起源状态；Genesis 只在某条已批准的物理规则需要时由适配层调用。

**Check：**在同一 seed/版本下重建同一初态；关闭重启后 O1 状态/事件摘要一致；重复观察或改变相机、帧率、暂停/显隐不改变 manifest/state/event hash；提供 tick 0 与 ONE 的真实 UE5 画面及相应 worker 日志。记录六类场所可辨认和地理连通的审查结果。

**Act：**若视觉质量不足，修改场景投影/资产；若状态或因果链不成立，修改起源契约/规则并重测；若性能或发布版接口出现可复现缺口，再比较插件/适配替代路径。由证据决定是否进入 TWO，不按概念叙述自动升级阶段门。

## 7. 开放决策与既有文档关系

1. 混沌世界中居民是否已经拥有独立灵域，或只在后续分化中取得可追踪灵域身份，需要叙事与契约共同裁定。
2. `ONE` 的第一条起源事件由世界时间、空间扰动、玩家介入，还是复合条件触发，尚未确定；首轮可使用显式命令作为技术验证入口。
3. “二”和“三”的具体哲学映射、守恒量和约束仍是候选，不能从本方案直接推出数值规则。
4. 现有 `chapter_one_cosmology.md` 以先天八卦世界为起点、把玩家称为外部变量；`edging_world_engine_model.md` 从 WorldSeed 直接生成卦域/实体。它们描述后续秩序或旧版建模，不覆盖本次新确认的混沌起源。后续 ADR 应明确衔接：现实操作者在世界外，世界内玩家化身属于世界之灵。
5. 初始视觉规模、城市复杂度和所用 UE5 资产须结合目标机器与内容许可评估；不预填未经测量的性能阈值。
