# 世界引擎演化原则（总纲）

> 本文件是 `edgeWorld / 易之世界` 世界引擎的顶层演化架构，统摄 `doc/world_engine_design.md`、
> `doc/edging_world_engine_model.md`、`doc/chapter_one_cosmology.md` 与
> `edging/docs/02-domain-model/edgefield-model.md` 中的术语。它是「处理原则」的架构化落地：
> 一句话总纲 = 文王六十四卦代表六十四种平行宇宙法则；漫游者以灵域适配当前宇宙，持续偏离会
> 令候选宇宙特性逐步渗化，达到关系阈值后完成跨宇宙迁移。先天演化是当前宇宙持续运行的基线，
> 后天灵域是玩家/NPC 嵌入并影响该基线的局部边界状态。

## 0. 研发边界、术语与交付阶段

### 0.1 “宇宙”与“地图”不是同一个维度

- **64 宇宙**是六十四卦对应的 64 套法则配置，不代表一次加载 64 份完整 3D 场景。
- **先天 8×8 地图**是漫游者可进入的空间图册；每格有一个卦域身份，可索引对应的宇宙法则。
- **当前宇宙**决定场景的主导规则；**候选宇宙**以受限权重叠加到局部/全局表现。第一版共享地形网格，
  通过地貌参数、材质色调和环境反馈体现法则渗化，避免复制 64 张地图。
- **灵域嵌入**是主体相对当前宇宙法则的持续适配状态，不是每轮重新生成的装饰数据。

### 0.2 状态权威与数据流

```text
当前持久世界状态 + 先天时钟
        ↓ 规则推进
当前宇宙法则下的 64 卦域状态
        ↓ 玩家/NPC 已批准动作（不可由前端重算卦象）
灵域适配度 / 偏离 / 候选宇宙关系压力
        ↓ 渐进过渡
同一地图上的候选宇宙特性渗化；达到阈值后更新主导宇宙
        ↓
保存状态与迁移原因 → UE5 发布版优先消费并呈现；Godot 作为辅助观察端按同一数据验证
```

规则运行时拥有唯一状态写入权。UE5 发布版是当前首选集成和呈现端；Godot 保留为辅助原型观察端。两端都不能自行决定宇宙迁移，且渲染帧不推进权威世界时间。

### 0.3 阶段性交付

| 阶段 | 研发目的 | 交付物 | 验收条件 |
|---|---|---|---|
| **A · 法则图册与迁移状态机** | 把 64 宇宙、四组关键关系和迁移状态变为数据/规则 | 64 条法则摘要、关系拓扑、偏离/渗化/迁移事件、状态存取 | 确定性；四组关系门槛不同；状态可保存并续算；前端输入不越权 |
| **B · 漫游地图闭环** | 优先在 UE5 发布版把当前/候选宇宙状态呈现在同一 3D 可漫游世界；Godot 保留为辅助观察器 | 8×8 地图数据、UE5 发布版地图消费者、HUD/区域法则反馈；Godot 可作为对照端 | UE5 发布版读取同一地图与权威状态；64 区/8 坐席；过渡权重有界；观察和帧率不改变状态；Godot parity 可作为辅助证据 |
| **C · 先天跨 tick 演化** | 让 64 卦域作为持久世界状态随时钟持续变化 | 存档世界状态、逐区基线/环境变量、自然恢复/稳定事件与回放 | 相同 seed+输入序列逐字节一致；无玩家时仍演化；读档续算一致 |
| **D · 后天灵域嵌入** | 让主体有位置、范围、灵域适配，并对附近世界施加影响 | 主体位置/影响核、纯物响应、至少一种 NPC 响应、空间事件日志 | 变化有空间局部性和衰减；效果来自已批准输入；可解释可回放 |
| **E · 长期塑界** | 让反复的局部扰动改变区域基准法则 | 区域规则记忆、阈值沉积、熵/能量边界、迁移和存档迁移方案 | 长序列累计有界；规则改变不瞬时污染全图；来源链完整 |

阶段 A/B 是本轮第一版的可交付范围；C 当前只接入了持久化迁移状态，完整区域自然演化仍属阶段 C。
阶段 D/E 不得因单轮灵域快照或规则改写函数存在就标成完成。

### 0.4 引擎集成路径

edgeWorld 自有规则、状态与因果契约不依附某一渲染引擎。第一条实现路线优先使用 **UE5 发布版**的成熟引擎、Runtime 插件扩展和现有渲染能力，通过插件/适配层连接 Genesis 与 edgeWorld 第四维状态演化。只有已批准契约在发布版 UE5 上经可复现原型验证确实无法满足，且插件/旁路方案也已评估失败后，才考虑修改 UE5 引擎源码。Godot、SceneKit 等端可作研究或对照观察器，不能因此把发布版优先路线反转成多端并列实现承诺。

## 1. 双轨演化

世界演化有且只有两条轨道，职责互斥、不可混用：

### 1.1 先天八卦 —— 世界基线（Pre-heaven Baseline）

没有玩家介入时，世界本体按**先天八卦**排布与演化。先天八卦是世界的「原初物质属性」与「自然节律」：

| 范畴 | 先天八卦负责 |
| --- | --- |
| 总体布局 | 8×8 卦域、方位、世界宏观地理结构 |
| 原初物质属性 | 八卦 → 地形基元（乾天/坤地/震雷/巽风/坎水/离火/艮山/兑泽） |
| 万物生长 | 纯物的初生/鼎盛/衰败/消亡四阶段生命周期 |
| 四时变化 | 四象节律（少阳/太阳/少阴/太阴）循环推进 |
| 宏观物理 | 山呼海啸、气象、地貌演变等「大到山海、小到树长」的自然过程 |

先天演化是**封闭、守恒、收敛**的：总能量恒定为 1，一切变化都是此消彼长，熵逼近临界时触发
收敛事件把世界拉回稳定态。这是世界的「天道」，不以任何个体意志为转移。

### 1.2 后天八卦 + 文王六十四卦 —— 玩家/用户触发的变化（Post-heaven Change）

玩家/用户动作是**外部变量**。它不直接改写世界，而是注入一条变化：

```text
玩家动作 a（八轴之一，强度 0.1…1.0）
        ↓
后天八卦投影（方位）→ 洛书数 → 动爻
        ↓
文王六十四卦 → 本卦 / 变卦
        ↓
变化灵域的属性更新
```

先天八卦决定「没有玩家时世界如何运行」，后天八卦决定「玩家介入后世界如何转变」。
这与第一章「先天八卦世界本体 / 后天八卦变卦」的因果链一致，是本总纲在第一章的特例。

## 2. 双轨渲染

专用游戏引擎必须区分两条渲染管线。这里的「渲染」不是纯图形输出，而是
**演化结果的「状态应用 + 呈现」**：

### 2.1 规则渲染（Rule Rendering）＝ 规则级演化

- **输入**：先天八卦规则集 + 世界时钟。
- **职责**：把先天基线演化应用到世界并呈现——地形、物质、生长、四时、山海气象。
- **性质**：静态、确定性、可复现。同一 seed 必然生成同一世界。它不感知玩家，只感知「道」。
- **对应现有实现**：`engine/world_engine.py`（世界原型）+ Godot 规则层。

### 2.2 edge 渲染（Edge Rendering）＝ 边界演化

- **输入**：用户/NPC 动作对世界产生的影响（后天变化）。
- **职责**：把后天变化呈现到世界的作用**边界/前沿**——万物被动响应刷新、NPC 反应/介入、
  玩家匹配结果。
- **性质**：动态、事件驱动、由主体动作触发。它是「变化」如何被世界看见并吸收的过程。
- **对应现有实现**：`engine/subjective_world.py` + `engine/chapter_one_runtime.py`。

> 一句话区分：**规则渲染画世界本来的样子；edge 渲染画世界因谁、因何而变。**

## 3. 万物有灵：灵域（Edge）统一抽象

### 3.1 灵域定义

万物皆有灵域 `E`——包括纯物、用户、NPC、灵体。灵域不是灵魂实体，而是该事物
**承载演化规则的边界状态**，含三个要素：

```text
E_x = < φ_x,  r_x,  ρ_x >
      │       │      │
      │       │      └─ 与其他灵域的关系（作用/被作用）
      │       └─ 演化规则引用（指向先天轨 or 后天轨）
      └─ 属性向量：九宫八卦共鸣系数矩阵（3×3，外八格=八灵共鸣、中宫=主观统合度）
```

`Edge` 是灵域的状态切片，`Edgefield` 是让切片有意义的完整状态承载上下文
（沿用 `edgefield-model.md` 的既有定义，统一到游戏引擎线）。

### 3.2 灵域的描述语言与五卦演化

灵域状态 `φ` 用**九宫八卦共鸣系数矩阵**描述——3×3 后天洛书布局，外八格为八灵共鸣系数、
中宫为主观统合度。它与 `subjective_world.py` 的基础灵体矩阵（`primal_spirit_matrix`）是同一结构。

由共鸣系数推出**本卦**（关键卦象），灵域的变化按五卦规则推演：

| 卦 | 灵域演化职责 | 状态 |
| --- | --- | --- |
| **本卦** | 内部动作的演化规则——灵域被自身内部动作改变的方式 | ✅ 已确认 |
| **综卦** | 外部动作的演化规则——灵域被外部动作改变的方式（反向视角） | ✅ 已确认 |
| **互卦** | 内外动作交汇的中间传导过程 | ✅ 已确认 |
| **变卦** | 动爻触发后的结果态 | ✅ 已确认 |
| **错卦** | 对立潜能 / 隐藏属性 | ✅ 已确认 |

哲学逻辑：**本=体**（自身怎么变）、**综=用**（被外部怎么变）、**互=过程**（内外怎么交汇）、
**变=果**（变成什么）、**错=隐**（藏着什么反面）。

例（需卦 ☵☰，坎上乾下）：本卦需 → 内部动作按「需之时、地」演化；综卦讼（天水讼 ☰☵）
→ 外部动作由「讼卦属性」的灵域动作改变。

**九宫系数 → 本卦** 采用候选 A（强弱合成）：最强共鸣的灵体为**下卦**（内在之体），
次强共鸣的灵体为**上卦**（外在之用）。实现见 `engine/edgefield.py: primary_hexagram()`。

**外部动作的判据**（可测试）：只有本卦等于本方综卦的灵域动作才能改变本方——
「能改变我的，是我的反向视角」。实现见 `EdgeFieldModel.evolve_external()`。

### 3.3 稳定灵域 —— 纯物，走先天八卦

纯物（树、山、海、石、遗迹）的灵域**稳定**：其演化规则引用先天八卦，随世界节律
缓慢演化。它们不主动变化，但**会被后天变化波及刷新**（见 §4 落点一）。

### 3.4 变化灵域 —— 用户/NPC，走后天八卦

用户/NPC 的灵域**变化**：其演化规则引用后天八卦，由自身动作与外部动作持续触发变卦。
变化灵域是世界的「变数源」。

## 4. 演化效果的三处落点

后天变化一旦产生，效果同时体现在三个地方：

1. **万物被动改变响应刷新** —— 纯物（稳定灵域）不主动变，但后天变化的边界扫过时，
   其灵域属性被刷新（如玩家涉水，水体的「坎」属性被扰动；玩家焚山，山的「艮/离」属性偏移）。
2. **NPC 反应 / 介入** —— NPC 是变化灵域，接收到后天变化后自身灵域再演化，产生行为、
   立场、介入（战斗、帮助、逃避、交易）。
3. **玩家匹配结果** —— 玩家灵域与当前事件/卦象/主导爻的匹配，决定其遭遇、定数与变数反馈。

---

## 5. 元机制：变化灵域改写先天规则（本总纲的核心）

变化灵域的演化效果有三层，层层递进：

1. **改自身**：`φ_x` 更新（变卦改变自身灵域属性）。
2. **改先天**：变化灵域能**改写先天灵域的演化规则** `A`——即后天行为可以改变世界基线
   本身的运行方式（例如反复的玩家行为让某卦域的地貌/气候/生长规则永久偏移）。
3. **改他人**：先天规则被改写后，**进而影响其他后天灵域**的规则与属性——形成
   「一个主体的变化 → 改写世界规则 → 传导到其他主体」的递归闭环。

**硬约束（防止世界漂移不可控）**：

- 先天规则改写 `M` 必须是**局部、带衰减**的：影响随距离与次数衰减。
- 改写量必须服从**收敛约束**：世界总熵不得因此无限发散，逼近临界即触发收敛事件拉回。
- 改写必须**可追溯**：每次改写记录来源主体、触发动作、卦象、改写的规则项与幅度。
- 主体**不能直接绕过世界仲裁**：它改的是「规则的边界」，不是「无视规则」。

## 6. 形式化（数学显式）

### 记号

- `W_t`：世界状态；`C_t = <era, cycle, phase, phaseProgress>`：世界时钟（四象）。
- `A`：先天规则集（八卦 → 地形/气候/物质/生长/四时规则表）。
- `H`：后天规则集（方位 + 洛书数 → 动爻；文王六十四卦 → 本卦/变卦）。
- `E_x = <φ_x, r_x, ρ_x>`：实体 `x` 的灵域。`r_x ∈ {A, H}` 决定其演化轨。
- 纯物集合 `P`（`r=A`），主体集合 `S`（`r=H`）。

### 演化函数

```text
// 先天基线（规则级演化）
W_{t+1} = X_A(W_t, C_t)
   约束：总能量守恒；yinQi + yangQi ≤ tileEnergyLimit；熵收敛。

// 后天触发（边界演化）
pressure   = proj_H(a, σ)        // 动作 a ∈ 八轴，强度 σ ∈ [0.1, 1] 投影到后天八卦
moving     = luoshu(pressure)    // 方位 + 洛书数 → 动爻（含证据、来源、映射公式）
hex        = wenzhou(moving)     // → (本卦, 变卦)

// 变化灵域自更新
φ_x^{t+1}  = P(φ_x^t, hex),      ∀x ∈ S

// 元机制：后天改先天
A^{t+1}    = M(A^t, Δφ_x)        // Δφ_x 为主体灵域变化；M 局部、衰减、收敛、可追溯
W^{t+1}    = X_{A^{t+1}}(W^t, C^t)
```

### 渲染函数

```text
Render_rule(W_t, A)  → 静态世界呈现（地形/物质/生长/四时/山海）
Render_edge(W_t, ΔE) → 边界呈现（万物被动刷新 / NPC 反应 / 玩家匹配）
```

## 8. 验证标准（可测试）

1. **双轨隔离**：无玩家动作时，`Render_edge` 不产生任何状态变化（世界只走先天）。
2. **确定性**：同一 seed + 同一动作序列，`W_t` 与两轨渲染结果完全一致。
3. **纯物稳定**：纯物灵域在无后天波及时不改变其 `r_x` 与 `φ_x`。
4. **元机制收敛**：任意动作序列下，`A` 的累计改写量有界；熵不因改写发散。
5. **元机制可追溯**：每次 `A` 改写都可定位到（主体, 动作, 卦象, 规则项, 幅度）。
6. **三落点可达**：一次后天变化能被观察到「纯物刷新 + 至少一个 NPC 反应 + 玩家匹配」。

## 9. 用户表现采集卡（Expression Capture Card）

> 实现：`engine/expression_card.py`；快照段 `edge_fields.expression_card`；
> 前端控件见 Godot `chapter_one.gd` 与 UE5 `ChapterOneSnapshot`。

**要解决的问题**：玩家原先只能给「一个动作轴 + 一个强度 + 一句文本」，文本仅做
关键词匹配，而灵域 φ 主要由 AI 决策驱动——玩家没有操作空间，世界反馈因此呆板。

**采集维度（玩家可操作面）**：

| 维度 | 取值 | 作用 |
| --- | --- | --- |
| 通道 channel | 言语 / 行动 / 意念 / 器物 | 用什么说 → 动作轴偏性 |
| 三才 target | 天 / 人 / 地 | 说向哪层 → **直接塑造灵域上／中／下** |
| 时机 timing | 当下 / 追忆 / 预取 / 恒常 | 说在何时 → 动作轴偏性 + 锐度 |
| 所 place | 内 / 外 / 近 / 远 | 说自何地 → 动作轴偏性 + 阴阳偏性 |
| 笃定 certainty | 0.0 … 1.0 | 说得有多锐 → 共鸣锐化 + 中宫统合度 |

**渲染规则**：采集卡 → 表达指纹（压力向量 + 区域权重 + 阴阳偏性 + 锐度 + 意象命中）
→ 九宫共鸣系数 → 本卦 → 五卦。

- 说**天** → 九宫上排（巽/离/坤）抬起 → 上卦强
- 说**人** → 中宫统合度抬起（中宫不是第九个灵体，是八灵共鸣的统合强度）
- 说**地** → 九宫下排（艮/坎/乾）抬起 → 下卦强

实测（同一动作轴与烈度，只改三才）：天 → 井、人 → 节（统合度 1.000）、地 → 涣。

**约束**：采集卡只渲染灵域，**不参与卦象与动爻裁决**——动爻仍由后天洛书规则给出，
确定性引擎仍是唯一裁量者。两引擎必须读到同一张采集卡（parity 门禁比对 `edge_target`）。

## 10. 先天世界：方位与时间

> 实现：`engine/world_engine.py`（`XIANTIAN_LAYOUT` / `xiantian_seat` / `WorldClock.xiantian_trigram`）；
> 快照段 `xiantian_world`；渲染器 `tools/render_xiantian_world.py`。

先天世界的**方位**与**时间**同样按先天八卦规则走，不是朴素线性排布、也不是均匀流逝。

### 10.1 方位：由方位角铺开

8×8 卦域按格子相对世界中心的**方位角**排布：每格的**上卦**＝它所在方位扇区的先天之卦
（外在方位），**下卦**＝该扇区内按到中心距离排序得来的先天次序卦（内在层次）。

- 取向采中国古地图惯例：**上南下北、左东右西**
- 八个方位各 8 格，64 格恰好覆盖 64 卦
- 第 i 区与第 i+4 区的平均方位角恰好相差 180°，所以**相对两区的上卦必互为相错**

于是「对宫」是货真价实的**方位相对**：上卦相错、下卦相同。§3.2 的四对对待在这张地图上
可以被断言，而不只是修辞：天地相隔（乾S↔坤N）、水火相对（离E↔坎W）、风雷相荡
（巽SW↔震NE）、山泽相通（艮NW↔兑SE）。

### 10.2 八灵的方位坐席

每个方位区恰好落一个纯卦，那就是该灵的坐席：
**乾居南、坤居北、离居东、坎居西、兑东南、巽西南、艮西北、震东北**。

`WorldEngine.xiantian_seat()` 给出坐席。第一章的八灵不再从原点按偏移量硬摊开，而是
各居其位——「万物有灵」在空间上就是一幅先天八卦图。

### 10.3 时间：时轮而非均匀流逝

时间由**四象**（宙）与**先天时轮**共同决定：

- 四象每推进一步，时轮走一卦，八时按先天次序（乾兑离震巽坎艮坤）循环
- 时卦以**阳爻数**为权修正地形：三阳之乾最升最暖、三阴之坤最沉最湿，其余居间

世界的「时」因此随先天八卦的阴阳消长起落，而不是均匀流逝。两引擎的 parity 门禁
比对时轮（`clock_trigram` / `clock_direction`）。

### 10.4 可漫游场景

`tools/render_xiantian_world.py` 除 PNG／ASCII 外，还导出**带地形摘要和 64 宇宙法则表**的地图数据
`models/xiantian_world_map.json`：64 卦域 ×（坐标／卦象／方位／高度／湿度／温度／biome／
是否纯卦），附 64 条法则摘要、四组宇宙关系、时轮和八坐席。两个前端据此建漫游原型：

| 前端 | 入口 | 漫游方式 |
| --- | --- | --- |
| Godot | `res://world_map.tscn`（`world_map.gd`） | W/A/S/D 平移、Q/E 升降、Shift 加速、右键拖动转视角 |
| UE5 | `-EdgeWorldMap` 启动开关（`AEdgeWorldMapActor` + `AEdgeWorldMapPawn`） | W/A/S/D 移动、Q/E 升降、Shift 加速、鼠标转视角 |

Godot 使用原生 `Node3D` 场景根节点与 GDScript 动态创建 `BoxMesh`、碰撞体、相机和 HUD；UE5 使用
`AEdgeWorldMapActor` 与引擎内置 Cube/Cylinder Mesh 的 `UInstancedStaticMeshComponent`。
Godot 通过 `res://world_map.tscn` 启动，键盘漫游；UE5 通过 `-EdgeWorldMap` 启用地图 GameMode，
使用地图模式专用的自由漫游 Pawn，不是完整第三人称角色模板。两边使用地图 x/y 与高度同一映射，
但尚不承诺材质、标签和地貌视觉逐像素一致。

`EDGEWORLD_XIANTIAN_MAP_JSON` 让两端使用同一地图 JSON；Godot 同时从
`EDGEWORLD_CHAPTER_ONE_JSON` 读取当前/候选宇宙叠加。UE5 使用同名地图环境变量或
`-EdgeWorldMapData=/绝对路径/xiantian_world_map.json`。第一版以受控地图浏览为目标，
地图生成的是格块原型，不是有角色胶囊/第三人称相机的完整玩家模板。
Godot 用候选法则温度提示色调渗化；UE5 将候选法则基准高度按快照过渡权重叠加到格块高度。
这是首版宇宙渗化视觉信号，尚非完整材质/生态切换。

### 10.5 64 宇宙的法则参数与关系通道

地图 JSON 的 `universes[0..63]` 以卦值为键，保存卦名、上下卦和由八卦地形规则组合出的法则摘要。
迁移关系 `universe_relations` 当前显式定义四组设计锚点：

| 卦对 | 关系类型 | 设计含义 |
|---|---|---|
| 乾䷀（63）↔坤䷁（0） | `opposition` | 天地两极，最高门槛 |
| 坎䷜（18）↔离䷝（45） | `opposition` | 水火/阴暗与明亮，最高门槛 |
| 巽䷸（27）↔震䷲（36） | `oscillation` | 风雷相荡，循环/多轴压力可积累跨界契机 |
| 艮䷳（9）↔兑䷹（54） | `permeable` | 山泽相通，允许较早渗化但迁移仍需积累 |

其余卦对第一版按六爻 bit 汉明距离建立确定性默认边，不替代后续经玩法校准的正式关系图。
`parallel_universe.py` 消费已批准动作轴压力，维护当前/候选宇宙、偏离、候选亲和度、过渡权重和迁移原因；
它不裁决本卦、动爻或变卦。阈值是原型常量，阶段 A 必须通过模拟校准后才能成为正式玩法数值。
