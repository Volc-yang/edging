# Edge World 工作日志 2026-09-20

## 今日目标

在第一章中明确并实现世界演化的因果层次：主观世界本体以先天八卦运行；玩家介入成为外部变量；世界潜意识依据后天八卦转变；周易六十四卦给出玩家遭遇的本卦、动爻与变卦；本地 Ollama 负责受约束的后天演化提案与玩家可见呈现。

## 完成事项

### 1. 第一章规则边界

- 建立先天运行次序：乾、兑、离、震、巽、坎、艮、坤。
- 建立后天八卦方位与洛书数映射。
- 将玩家介入定义为动作轴、强度和行为表达三个字段。
- 玩家动作限制在八个基本轴：`ascend`、`receive`、`flow`、`illuminate`、`awaken`、`adapt`、`stabilize`、`exchange`。
- 强度限制为 `0.1...1.0`。

### 2. Ollama 权限模型

- Ollama 只能提交受限的动作压力，不能直接指定动爻、本卦或变卦。
- 重点灵体由最强动作通过固定规则推导，消除了“动作与灵体矛盾”的无效状态。
- 决策契约升级为 `edgeworld.chapter-one-decision.v2`。
- 世界快照契约升级为 `edgeworld.chapter-one-snapshot.v2`。
- 第二次 Ollama 调用只负责把已确定的卦象呈现为场景、征兆和玩家下一步提示。
- Ollama 不可用或输出非法时，使用可回放的确定性规则回退。

### 3. 周易遭遇生成

- 先天当前相位与玩家动作组成玩家进入世界后遭遇的本卦。
- 玩家变量与 Ollama 动作压力经过后天方位、洛书数映射为动爻。
- 变卦表示世界主观潜意识的转变。
- 快照记录本卦、动爻、变卦、后天主位、玩家变量和 AI 压力，支持完整回溯。
- `yijing_text.json` 的原典完整性通过 `canonical_text_available` 显式标记；缺失内容只显示上下卦结构，不由 AI 伪造经典原文。

### 4. Godot 引擎与诊断预览

- Godot 4.7 前端增加玩家动作、强度和行为输入。
- Xcode/SceneKit 诊断预览增加相同的玩家介入控件，但它不是第二套游戏引擎实现。
- Godot 与诊断预览均显示先天相位、后天主位、本卦、动爻、变卦和 Ollama 遭遇文本。
- Godot 是第一章主实现；UE5 作为读取同一快照的正式对比实现。
- Godot 和诊断预览只读取同一份已批准快照，不各自计算卦象。

### 5. UE5 对比实现

- 将 `/Volumes/DevSSD/Unreal/Projects/EdgeWorldUE` 从官方空模板扩展为第一章 UE5 对比实现。
- 新增共享快照解析器，严格校验 schema v2、先天/后天秩序、八灵与动爻范围。
- 新增 `AChapterOneWorldActor`，在 UE5 中生成相机、光照、八灵球体与遭遇摘要。
- 新增 `AEdgeWorldGameMode`，启动时自动生成第一章世界。
- 新增 `UEdgeWorldSnapshotCommandlet`，支持无界面契约验证。
- UE5 5.8.2 Editor Development 目标实际编译成功。
- UE5 游戏模式实际运行并输出 `EDGEWORLD_UE_CHAPTER_ONE_READY`。
- 新增 `tools/validate_godot_ue5_parity.py`，逐项比较 Godot、UE5 与源快照。
- 当前对比结果为 `status: match`。
- 新增 `UChapterOneControlWidget`，在 UE5 中提供八类动作轴、强度与玩家表达输入。
- UE5 的 Ollama/确定性回退按钮异步调用共享 Python 规则门，完成后原位重载八灵与遭遇，界面线程不被模型调用阻塞。
- UE5 不接受玩家直接指定卦象或动爻，交互层没有绕过第一章规则边界。
- 修复 Godot 动态界面的中文字体回退，改为加载系统实际存在的 `Hiragino Sans GB.ttc`，无界面运行也不再产生 FreeType 错误。
- 修复 UE5 球体误用默认灰色网格材质的问题，显式使用可着色的 `BasicShapeMaterial`。
- 修复 UE5 3D 标签背向相机和中文距离场字体缺失问题，改为正向英文标识与意识数值；中文语义保留在 UMG。
- 将 UE5 控件树创建移到 `RebuildWidget` 生命周期，运行时 UMG 玩家介入面板已实际显示。

## 已知问题与风险

1. `engine/yijing_text.json` 当前虽然覆盖 64 卦名称、序号和符号，但只有部分卦包含完整卦辞、大象和爻辞。
2. 后天动爻映射目前是第一章的工程化规则，需要结合后续玩法测试校准玩家可理解性与事件多样性。
3. 当前世界快照是单轮输出，尚未形成跨 tick 的持久历史、回放索引和存档迁移机制。
4. 系统 Python 环境缺少部分完整测试所需依赖；完整回归应继续使用工程 `.venv`。
5. UE5 已具备 C++ 运行时 UMG 输入与热重载闭环，尚缺视觉主题、灵体点击交互、资产化关卡和视觉截图基线。
6. UE5 工程位于外置盘且尚无 Git 历史，需要纳入可恢复的版本管理方案。
