# Edge World 工作日志 2026-09-21

## 今日问题

试玩时发现：只修改玩家描述文字并再次点击生成，卦象保持不变。

## 根因

- 两个引擎每次都调用 `tools/run_chapter_one.py` 的默认 `tick=1`。
- 第一章本卦由先天相位和玩家动作轴决定，动爻由后天压力、洛书数和 tick 决定。
- 自由描述会进入 Ollama 观察和遭遇呈现，但按权限边界不能直接指定卦象。
- 因此固定动作、强度和 tick 时，即使文字变化，规则层仍可能得到同一卦象。

## 修复

- 为共享 CLI 新增 `--advance`，从现有 v2 快照读取 tick 并递增一轮。
- Godot、UE5 和 SceneKit 的推演按钮统一传入 `--advance`。
- 保留 `--tick N` 作为可回放的固定时序入口。
- 对缺失快照从第 1 轮启动；损坏、旧 schema 或无有效 tick 的快照明确报错，不静默重置时间。
- Godot 状态栏和 UE5 遭遇摘要增加当前轮次显示。
- UE5 快照读取器增加正整数 tick 校验。
- 修复 Godot↔UE5 对比工具使用 PIPE 捕获 UE 后台子进程时可能等待 EOF 的问题，改用临时文件捕获。

## 验证

- 修复前复现：两种描述在固定第 1 轮均为无妄、动爻 2/3、变卦讼。
- 离线连续提交：第 1 轮无妄→讼；第 2 轮随→否。
- 本地 `llama3.2:latest` 连续提交：第 2 轮随→同人；第 3 轮噬嗑→履。
- Python：87 项测试通过。
- Godot：headless 运行通过。
- SceneKit：Swift 构建通过。
- UE5 5.8.2：Editor Development 编译通过，Commandlet 校验通过。
- Godot↔UE5：第 3 轮噬嗑→履、震/东/洛书三，`status: match`。

## 卦爻抽象、预判与世界反馈闭环

- Ollama 提示词改为先识别玩家动作、对象和已经/试图造成的世界变化，再投影为受限八动作轴；
  “唤醒之物喷出火焰”可同时识别 `awaken` 与 `illuminate`，但模型仍不能指定卦或爻。
- 快照新增 `encounter.abstraction`，保存表达、声明动作、语义压力、上下卦依据和逐爻证据。
- 多个动爻中按证据选择 `governing_line`，并返回主导爻名、阴阳、原典爻辞和选择依据。
- 新增 `world_response`：卦辞/主导爻辞预判、受限世界控制指令、目标灵体应用前后状态和玩家反馈。
- 主观世界模型实际更新目标灵体的意识、自洽、熵与卦值；Godot、UE5、SceneKit 根据同一控制
  指令改变目标灵体的尺寸、位置和发光表现。
- 接通仓库内已校勘语料：64/64 卦辞、64/64 大象、384/384 常规爻辞；不再以结构占位代替原典。
- 示例实测（本地 `llama3.2:latest`，第 8 轮）：复卦、主导六四“中行独复”、变卦贲；规则将
  “震发”作用于震灵并返回应用前后的主观状态。
- 发现 `llama3.2:latest` 会漏掉明确的“火焰”语义，因此增加可审计的规则侧关键词证据下限，
  与模型压力合并而不是让模型单独掌权。第 10 轮同一句输入稳定识别 `awaken=0.8`、
  `illuminate=0.8`，得到随卦上九→比，并将“显明”控制实际应用于离灵（fire）。
- 实机视觉复核通过：UE5 已移除重复方向光警告，右侧面板显示卦辞、主导爻辞、预判和反馈；
  Godot 显示同一内容，两边均对离灵执行放大、位移和发光响应。
- 更新后验证：Python 90 项测试通过；Godot headless、SceneKit 构建、UE5 5.8.2 Editor Development
  编译与 Commandlet 均通过；Godot↔UE5 对第 7 轮颐→蒙验证为 `match`。

## 规则说明

描述文字影响 Ollama 的受限后天压力提案与玩家可见叙事，但不能直接选择本卦、动爻或变卦。
每次点击推进 tick，使玩家的连续介入发生在不断演化的先天世界中；动作轴、强度、世界时序和
通过规则门的压力共同决定最终卦象。
