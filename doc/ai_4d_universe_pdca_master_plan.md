# edgeWorld 4D 世界游戏：递归 PDCA 开发架构

状态：2026-11-01 v0.2；规划基线 `abc990a`，统筹分支 `codex/universe-pdca-master`。本文规定**怎样开发和控制开发过程**。载具登陆、游玩和 AI 4D 数字宇宙是产品目标与验收背景；本计划不替用户制定玩法规则、物理法则或世界演化规则。具体产品契约另由相应技术任务评审。

## 总 PDCA 节点 G：交付可验证的 4D 世界游戏

| 阶段 | 总计划的方法与产物 |
| --- | --- |
| **Plan** | 从产品目标、既有 4D 契约和当前证据定义版本目标、范围、不可变约束、完成门和资源预算；拆成具有单一 owner、独立交付、明确依赖的任务 DAG。先冻结跨任务接口，再放行下游实现。每张任务卡有自己的 PDCA。 |
| **Do** | 按拓扑顺序派发 ready 任务；并行任务独占文件/接口或使用版本化共享契约。每个写任务在独立 Git worktree/分支开发并提交独立 PR。统筹任务只负责接口裁决、审查、集成和上下文。 |
| **Check** | 任务 owner 自测，独立 reviewer 核对差异与原始证据，集成 owner 检查跨任务接口和端到端场景。每个门预先定义可观测方法、输入/构建身份、阈值、证据位置和 `pass/fail/inconclusive`。不能用提交、编译或截图替代未执行的检查。 |
| **Act** | 对照目标分析差距及根因置信度；接受、局部返工、拆分、延期或停止任务。失败只重开受影响节点与其下游。更新 DAG、任务登记、决策与下一轮入口，提交精简上下文；清理已审查合并的干净 worktree。 |

总评价维度：**目标覆盖**（是否交付约定能力）、**契约正确性**（权威状态/时间/观察边界）、**集成可用性**（UE/Genesis/AI 等接口）、**运行证据**（可复现、可恢复、性能/视觉实测）、**开发可控性**（依赖无环、owner 清楚、PR/证据可追溯）、**风险与成本**。各维度分别评级，不以单个演示画面或一个总分掩盖失败门。

## 可递归的任务节点契约

每个节点 `N` 均记录 `id,parent,version,owner,status,depends_on,inputs,owned_paths,outputs`，并填写：

1. **Plan：**目标、输入版本、假设、步骤、依赖、接口、资源和预设完成门。
2. **Do：**最小可审查交付及边界；执行日志指向准确提交与环境。
3. **Check：**自测、独立检查和集成检查分别由谁做、用什么输入/方法/阈值、原始证据存放何处、实际结果是什么。
4. **Act：**事实、推断、缺证、差距原因、评价裁决及下一动作；失败后更改哪些节点/边，哪些已完成节点保留。

父节点通过的条件是相关子节点通过且父级集成 Check 通过。若某子节点过大或接口不清，再用同一结构拆子节点。拆分直到任务能由一个 agent 在独立 worktree 交付并让另一个 agent 审查；不以“每个函数一个任务”制造无意义碎片。

## 开发过程 DAG

```text
G0 目标/基线与质量门冻结
 ├─ G1 架构与接口分解 ─┬─ G2a 4D 状态/规则开发树 ───┐
 │                    ├─ G2b 物理适配开发树 ──────┤
 │                    ├─ G2c UE 呈现/交互开发树 ─┼─ G3 纵切集成 ─ G4 独立验收 ─ G5 复盘/发布/下轮
 │                    └─ G2d AI 生成/提案开发树 ──┘
 └─ GQ 证据/质量工具与资产规范 ───────────────────┘
```

`G2a–d` 是**开发工作流分支**，不是预先批准的游戏规则。G1 冻结共享数据和职责接口后，它们可并行；GQ 可从 G0 起并行。G3 负责跨分支集成，G4 须由实现 owner 之外的 agent 检查。G5 的 Act 决定下一轮 DAG；不能从 G2 的代码完成直接跳到发布。

| 节点 | 依赖 | Plan / Do：执行方案 | Check：方法与证据 | Act：分析与评价原则 |
| --- | --- | --- | --- | --- |
| G0 目标和基线 | 无 | 版本目标、目标硬件/规模、已有证据、非目标、质量门与预算；确认主工作区脏改动 | 目标可写成可运行场景与可量测门；检查来源和未决阈值 | 冲突先裁决；未批准的阈值标暂定，不拿事后结果倒推标准 |
| G1 架构与接口 | G0 | 划清 4D 权威、AI 提案、Genesis 物理候选、UE 观察/交互，版本化请求/结果与数据所有权 | 契约审查、依赖和写入路径无环/无冲突、最小集成探针 | 优先 UE5 发布版插件；只有已批准契约可复现缺口和替代方案失败才评估源码改动 |
| G2a 4D 开发树 | G1 | 逐个小版本开发状态、时间、演化、存储、恢复等能力；每个叶节点独立 PDCA/PR | 固定输入重演、事件/状态摘要、幂等、恢复、历史只读 | 分离规格错误、实现错误和证据缺失；不把渲染帧当权威时间 |
| G2b 物理开发树 | G1 | 将物理需求拆为可测的 Genesis 适配任务；固定单位、步长和状态交换 | 输入/轨迹/恢复对照与误差预算；版本/配置可追溯 | 物理行为缺口先评估模型、参数和适配边界；旧单刚体探针不代表完整物理系统 |
| G2c UE 开发树 | G1 | 场景分区、资产/材质、4D 投影、交互与输入分别成卡；发布版引擎优先 | Metal 实图、交互脚本、同状态多视角、权威只读哈希、帧时间 trace | 程序代理/视觉质量/物理正确性分开判；许可与素材来源独立核查 |
| G2d AI 开发树 | G1 | 模型/提示/数据/提案接口、拒绝条件、评估集分成独立卡 | 固定样本的接受/拒绝/复现记录；提案不能绕过权威规则 | 分析生成质量、偏差和因果错误；模型输出不直接等于已提交世界状态 |
| GQ 证据基础 | G0 | 构建、seed、配置、资产来源、原始日志/图/轨迹与摘要索引约定 | 随机抽取证据可定位准确构建和步骤；无输出判 `inconclusive` | 缺证补采，故障先固定原始现场；不盲改实现 |
| G3 集成 | G2a–d、GQ 中本版本所需叶节点 | 用版本化接口组装一条端到端纵切，记录基线及合并提交 | 契约兼容、运行路径、状态读写隔离、恢复和性能集成检查 | 失败按接口归属回退到最小节点，保留独立已过任务 |
| G4 独立验收 | G3 | 非实现 owner 按 G0 质量门运行真实场景 | 保存原始录像/日志/哈希/trace，逐门判 `pass/fail/inconclusive` | 评价目标覆盖、真实体验、可靠性与限制；不能用 PR 合并代替验收 |
| G5 复盘与下轮 | G4 | 汇总全部任务状态、PR、证据、风险和下一轮 ready 队列 | 对照 G0；核对 worktree/分支/主工作区、遗漏任务与上下文 | 接受或局部重开；更新 backlog/登记并 commit，清理仅干净且已集成的 worktree |

## 本轮规划任务卡与派发门

当前只派**过程架构**任务，禁止把它们扩展为游戏玩法设计或大规模实现：

| ID | owner / 独占交付 | 方案、Check 与 Act |
| --- | --- | --- |
| F0 框架契约 | 过程架构 agent；`doc/pdca_f0_framework_proposal.md` | 定义节点状态机、递归拆分/停止条件、DAG 拓扑/并行派发规则、任务卡字段和变更控制；用当前 Chaos/Realism 任务作回放检查，发现不可表达的状态就修订模板 |
| F1 质量与证据 | 独立验证 agent；`doc/pdca_f1_quality_proposal.md` | 定义自测/独立审查/集成门、原始证据、构建身份、pass/fail/inconclusive 和阈值冻结；用现有 V1→T1-VF→V2 失败返工链验证可追溯性 |
| F2 任务编排 | 统筹 agent；`doc/pdca_f2_orchestration_plan.md` | 将框架映射到 subagent、worktree、PR、新对话、反馈和上下文提交；检查 owner 无重叠、依赖无环、失败/等待输入可恢复 |

F0 与 F1 可并行；F2 依赖两者。主任务审查 F0/F1 的独立 PR 后冻结框架，再发布 G0/G1 和产品技术任务。每个写任务独立 worktree/分支，PR 指向 `codex/universe-pdca-master`。主工作区 `feature/edge-world` 的未提交改动保持原样。

`serial-firmware-loop` 可复用的仅是循环纪律：绑定构建/输入身份、完整保存原始证据、限定观察窗口、无信号判不确定、诊断后再修复和复测。串口/烧录/ELF 规则不进入通用 PDCA skill。Google 对比原文未找到，现阶段只记为待核实背景，不据此制定开发流程。
